Ambient Spawn System — CHANNEL = ALLEGIANCE (CRACKED + IN-GAME PROVEN 2026-08-17)

Three sessions were spent editing the CAST. The cast was never the lever.

An AI/SpawnAmbient/AITypes record carries no cast — it carries an ALLEGIANCE. Owner_Infantry, Invader_Infantry and Enemy_Infantry are identical in every populated field except one Int, GruntPlayerFollowerStatus, which partitions all 250 records with zero exceptions (the name prefix predicts it in all 250):

status n family
0 129 enemy / wildlife / DEBUG — every Enemy_*, Balrog
1 42 PLAYER ALLY — the humans: Gondorian_Soldier/Captain/Enlisted/General/Trainee/ShieldMaiden/Medic*, DLC4_Easterling_Archer/Defender/Infantry, GP_Ranger, GP_Ratbag, Gollum, *_Friendly, *_Follower
2 24 Owner (area garrison) — all Owner_*
3 17 Invader — all Invader_*
4 / 5 19 / 19 FortAssault_Owner_* / FortAssault_Invader_*

Two structurally different channel kinds (per-record descriptor variants in one category): 166 of 250 have fc=6 and NO Entries field at all (FactionMember-selection path); 84 have fc>=8 with Entries -> _StructuresAISpawnAmbientTypeEntry (template path). Writing a template into an fc=6 channel's Entries writes a field that record does not have — that is why every cast-swap attempt produced nothing.

CORRECTED 2026-09-30 — that "no Entries" reading is Anvil's DISK view, not the live record. Live, DLC_AI_Talion and Gondorian_Soldier (both "fc=6" above) decode with header_fc 13 and an Entries array of one _StructuresAISpawnAmbientTypeEntry primary (cell 0 Int = 0, cell 1 Template -> AI/Templates::AI_Talion / ::Gondorian_Soldier). The engine's own channel resolver 0x1B3098 walks that array (field accessor 0x1B3DD0, template 0x1B3CFC) and returns the template - measured by live-backed emulation on both channels. So the cast-swap failures were not "writing a field the record lacks"; re-check that ruling before building on it.

THE ENGINE SUBSTITUTES Enemy_X -> Owner_X | Invader_X AT LOAD. 11 live channels are authored NOWHERE in island's 228 layers (Goblin_Difficulty 1,001 live; every Invader_*), while Enemy_DifficultyAny has 1,059 authored cells and 0 live. Status-1 human channels are NOT substituted — Gondorian_Soldier is authored 155 times and appears live 49 times under its own name. So a disk edit that writes a HUMAN channel survives load; one that writes Owner_*/Enemy_* is pointless.

+0x0F0 sub-object vtable 0x1DB7120
+0x158 AI/SpawnAmbient/Areas (100%)   +0x160 AlarmAreas (27%)

6,323 live in island / 3,993 in Minas Ithil. Position comes from the AI NODE, not the spawner row — byte-exact searches for placement coordinates in layer files return 0/400 while world_join's control returns 3,349 hits. ~2,075 authored rows -> 6,323 live placements (3.05x). Density knobs are on _StructuresAISpawnAmbientPredicateEntry (121 primaries): RandomWeightRange (Enum = float-pool min/max), WindowLength, MustBeOffScreen, MustBeLineOfSight.

SpawnManager+0x190 IS THE AMBIENT-OWNED COUNT, NOT THE ARRAY LENGTH. Measured n=4: array 66 / +0x190 27 / removal-bearing 27; 112/31/31; 43/41/41; 23/23/23. The discriminator is entry+0x28 (the AI/SpawnAmbient/Removal record). Entities spawned by a MOD carry none and are invisible to it, so sow_war_spawner.hpp's "+0x190 == the entity-array length" is wrong — that reading was taken when the array happened to be all-ambient, where the two are indistinguishable. True occupancy is (end-begin)/0x40. Upside: mod spawns do NOT consume the ambient budget, so MaxAmbientAI (+0x180) and an additive spawner are independent levers.

IN-GAME PROVEN 2026-08-17 — pointing a live placement's +0x1C0 at a status-1 channel makes that spawn point produce a HUMAN, and the Love/Hate matrix makes the orcs engage with no further wiring. Controlled (additive War Spawner OFF, so it could not confound; it cannot produce a removal-bearing entity anyway): before 23 ambient-owned / 0 human; after 59 ambient-owned / 10 human (Gondorian_Soldier x10). Then at scale: 1,200 conversions across Minas Ithil, 0 failed, no crash, spread over MI_NobleQuarter 493 / MI_CommonQuarter 327 / MI_TradeQuarter 236 / MI_InternmentCamp 89 / MI_Gorge 50 / MI_RoyalTerrace 5.

Converting changes the MIX, not the population — raise MaxAmbientAI too or you get the same headcount in different armour. Convert a RATIO (~40%): converting everything transfers the city rather than starting a war. Skip Prisoner/Graugapult/Closet channels — staged content, and converting them reproduces the documented "humans in cages" result.

Arena / Pit Fight System (DECODED 2026-04-16)

Built on the SimEvent framework. Game internally calls pit fights "Arena".

Architecture: SimEvent defines the event -> SimEventChance controls win probability -> SimEventParticipant defines who fights -> Gauntlet wraps multi-stage fight pits.

Key categories and record counts:

Category Records Purpose
Faction/Events/SimEvent 431 Event definitions (Arena, Duel, Feast, etc.)
Faction/Events/SimEventChance 34 Win probability formulas
Faction/Events/SimEventParticipant 572 Participant configs
Faction/SimEvent/Gauntlet 4 Multi-stage pit fights (Island x3, SnowMountain)
Faction/SimEvent/GauntletTier 4 Tier configs (IslandTier1-3, SnowMountainTier1)
Faction/SimEvent/GauntletTierStage 4 Per-stage fight setups
Arena/CameraDirector 1 Camera control (Duel_ACD)

SimEventChance Field Layout — RE-DERIVED 2026-08-07 under the slot law (live + disk agree 8/8).

The old idx*4 table here was dense-era: right field NAMES, wrong CELLS. It listed +0x000 StartChance = 0.0 and +0x008 HenchmanDeltaScalar = 0.05; the value 0.05 is actually CharacterLevelDeltaScalar, and StartChance on Arena is 0.5, not 0.0 — so "Arena starts at zero and is decided by bodyguards" was an artifact, not a finding. Slots below are link, offsets are link*8. Verified against the running game (decode_record) AND the shipped GADB — every scalar identical on both sides.

3 +0x018 TotalInteractionScoreDeltaScalarMax Float 1.0

Win formula: chance = StartChance + (levelDelta * LevelScalar) + (henchmen * HenchmanScalar) + (IS * TotalISScalar)

Key SimEventChance records (StartChance / CharLevel / Henchman / Supporter, live-verified):

  • Arena — 0.5 / 0.05 / 0.15 / 0.0 — the pit-fight baseline is a coin flip, not 0
  • Default_2orc_arena — 0.5 / 0.02 / 0.15 / 0.15 — default 2-orc arena
  • Duel — 0.5 / 0.02 / 0.15 / 0.15 — nemesis duels (identical to Default_2orc_arena)
  • SubjectAlwaysWins — StartChance 1.0, every scalar 0, the two *Max fields -1.0
  • SubjectAlwaysLoses — StartChance 0.0, every scalar 0, the two *Max fields -1.0 (the two forced outcomes differ ONLY in StartChance — the old table gave both 0.0, which made them indistinguishable)
