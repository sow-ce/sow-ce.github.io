Engine anchors

The facts nearly every task needs. Details: kb/engine-anchors.md, kb/binary-code.md, kb/factionmember.md, kb/gamedb-schema.md.

  • Image vs heap. ShadowOfWar.exe always loads at 0x140000000 (RELOCS_STRIPPED, no DYNAMIC_BASE): image and static addresses are fixed, absolute = base + RVA. The HEAP moves every launch: never cache a heap address across sessions; stamp evidence with pid / base / session.
  • Code lives in two sections. .arch (0x1000-0x1D87C00) and executable .bss a (0x2C89000-0x729714D, the protector's region, reached only through vtables, so callers_of == 0 there proves nothing). .text is a 20-byte decoy; vtables live in .xtext. Take executability from the section table. .pdata is not the function universe (leaves have no entry, 26,293 entries are fragments): the function list is the xref index's.
  • Managers. GameManager [base+0x26FFAA8]. FactionSystem FS = [GM+0x6C68]: pools FS+0x68 (0xC0 each, members +0x18/+0x20; the MainGame pool holds every captain), army contexts FS+0x98 (38 x 0x290, ctx = entry+8), current region FS+0x1B0 (record name), its faction FS+0x1B8. Six "managers" are fake and must never be used: AIManager 0x2A34D00, PlayerManager 0x2A34BE0, ArmyManager 0x2A34B88, FortressSystem_Global 0x2A34C08, CombatManager 0x2A34CF0, InputManager 0x2A34C90.
  • In the world? SpawnManager [base+0x26FFBE8] is NULL at the main menu. Safe to write = it is live AND spawned > 0 (call("write_guard"); the player object is persistent and proves nothing). SpawnManager+0x190 is the AMBIENT-owned count, not the array length; entries are 0x40 bytes with the character at +0x20. It is reallocated mid-travel: never keep the pointer.
  • Player. [base+0x2797808] = first entry of the player list [base+0x2A34C68] (long misnamed NemesisManager). CGameClientShell [base+0x26FFA98]: +0x888 player, +0xE50 load task (a NEW pointer there = a load starting).
  • FactionMember (vt 0x1FD5EA0) is 0x528 bytes. FM+0x530.. is NOT the FM: the appearance object is [FM+0x2D8], addressed as [FM+0x2D8] + (off - 0x530). Valid FM = [FM+0x178] is a GameDB record. +0x168 seed, +0x174 pool index, +0x178 faction, +0x188 combat tree, +0x198 / +0x1E0 trait vectors, +0x268 row record, +0x270 personality, +0x278 class, +0x318 role, +0x328 tribe, +0x390 rarity, +0x3A0 builder, +0x498 inline name (Latin-1), +0x4B8 level (the UI shows +1), +0x508 nemesis bits (engine setters only), +0x51B seat column.
  • CCharacter. +0xAC position (cm), +0xB8 rotation QUATERNION (x, y, z, w; +0xBC is not a yaw), +0xC8 scale, +0xE2 bit 0 visible, +0x26A8 combat object, +0x2340 visual, +0x2348 VisualComponent (inventory), +0x23B8 follower byte, +0x2410 alignment.
  • GameDB record. +0x00 u8 field count, +0x01 0x0A (primaries 0x00), +0x08 descriptor run, +0x10 instance, +0x18 category, +0x20 name. Secondary stride 0x28, primary 0x20; a category's name is at cat+0x00.
  • Slot law. cell = instance + link*8 (descriptor +0x0E); descriptor +0x0C is the element COUNT (0 = owns no cell); packed bools = bit link%32 of cell link/32; vec slots hold POINTERS to deduplicated, SHARED blobs; type 5 = StringEnum (P919 of a NAME, never a pointer); type 7 = pointer to a shared float-pool (min, max) pair; types 10 / 11 = RecordLink to a secondary / primary record on disk (live descriptors say 10 for both: a link into a _Structures* category targets its primaries). Address cells only through the record's OWN descriptor run.
  • Names. RecordLink = (cat_idx*16)<<16 | rec_idx. P919 hash: h = h*919 + LUT[c] (LUT at 0x1DB50D0; StringHash 0x423E70 seeds from r8). 14.6% of record names exist in several categories: always resolve with category=.
  • Threads. Anything that allocates in the engine, dispatches to scripts or rebuilds a world object runs on the MAIN thread (native pump / main bridge; exec_main holds the cross-process mutex). The render thread may read. The main thread has no SEH net. Engine asserts are null writes at 0x819113 (RCX = message).
  • Focus and loads. The game pauses its simulation while unfocused: a stale heartbeat or a command stuck "queued" usually means tabbed out. Some loading screens re-deserialise GameDB instance state, and a region change resets bundles and animation pushes: re-arm live edits per load, never write during one.

Laws

One line each; full text and history in kb/hard-won-rules.md and the topic file named.

  • Never write FM / SMC / inventory / GameDB while loading: the deserialiser is rebuilding them (crash 2026-07-06).
  • Never memcpy-clone an entity or inject into SpawnManager; create objects through the engine's factory (kb/live-world-objects.md).
  • Never bulk-mutate hot-thread GameDB domains (NativeLife, Camera, Interface/WorldUI, AudioHook RTPCs, Profile, AI/Sensors, _Structures*) with int / vec / enum / FK writes. Repoint an enum cell only COLD, guarded on its old value (kb/army-menu.md camera).
  • Never write raw bytes at a vec slot or into a shared vec blob from a bulk tool; packed bools are single-bit read-modify-write; never dereference a type-5 cell (kb/gamedb-schema.md).
  • A RecordLink write must match the field's DECLARED type: SetLink only checks it is some record (crash at the shot, 2026-10-07, kb/quests-story-scenes.md savior).
  • A record with header byte +0x01 bit 0x10 (every BlendDB .bvr record, 0x1A) is a native struct: write instance + SlotOffset, never instance + link*8 (kb/gamedb-schema.md, 2026-10-27).
  • Never modify shared GDB records (Smp wrappers, Facial chains).
  • Never write FM+0x508 / +0x510 / +0x51A / +0x2A8 raw; nemesis bits go through the engine setters (kb/factionmember.md).
  • Identity-scale look changes (body, class, tribe, catalog head) use RebuildDirect 0x1BC3AA8, never UpdateVisualModel 0x62EB14 on a spawned orc (2 crashes). Changing body type on a loaded orc crashes: change looks atomically or while unloaded.
  • An engine object's own bytes never prove it is alive: re-find it in the engine's container, on the main thread, in the job that uses it (tint keeper use-after-free 2026-10-23).
  • Never write repeatedly to scanned world-object addresses without re-checking the vptr every pass; never restore by arithmetic: journal and restore with a still-ours check.
  • Re-resolve heap pointers on every use: SpawnManager and character controllers are replaced during travel and respawn.
  • In-process heap scans never run on the render thread, never read PAGE_WRITECOMBINE / NOCACHE pages and never cap region size (the Havok heap is one 512 MB region; reach it through [base+0x2A86760]+0x20).
  • Create an approved MinHook at boot and only enable / disable it later: late trampolines fail with MH_ERROR_MEMORY_ALLOC.
  • Framework memory read back through GDBRuntime must sit above 16 MB.
  • Runtime material slots: kind 0 solid, 1 translucent, 2 depth proxy (setter 0x17AF0C, main thread).
  • Rebuild a drawn weapon with the holder pair 0x3FD21C (hide) then 0x3FD204 (show); 0x40000C / 0x3FD228 only build an empty holder.
  • A malformed .fxp stalls the resource loader until restart. Ship a composed effect only after the engine check AND the value guard: load-time acceptance is not play-time safety (crash 2026-10-20).
  • Script-only natives (NPC::SetAlignment and the other users of 0x503EF8) fault from the bridge: run them inside an engine-dispatched handler.
  • A scene's target must still be active (in SpawnManager, alive, has an inventory), re-read in the same main-thread tick (crash 2026-10-14).
  • Never null an engine callback that also retires state (the GARRISON header callback 0x1983288).
  • Unused SQ03 animation slots must hold a valid quaternion; zero = engine assert = crash.
  • One owner per shared engine cell: share it through an owner-counted gate (framework/sowframework/sdk/sow_save_pause.hpp), never two independent gates.
  • Always 64-bit reads for pointers.
