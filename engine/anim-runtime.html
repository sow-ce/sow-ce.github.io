M = [[char+0x110]+0x1C0] (model object vt 0x1F6F950 -> model animation instance vt 0x1DA9700, 45 / 45). M+0x08 = vector of 0xA0-byte trackers, one per active clip; M+0x50 = the skeleton resource (begins with its own path); [[M+0x50]+0xB0] = the clip table object (vt 0x1E6F3F8), member list +0x78 (0x38 entries {+0x20 path, +0x28 anim object while loaded}); M+0xC8 pose-job descriptor, M+0xD8 its 20-byte blend entries (== tracker count, 36 / 36); M+0x118 time source; M+0x128 job submitted, +0x12A needs eval, +0x12B dt was 0.

tracker field (static: 0x17620C / 0x17674C / 0x175F04)
+0x02 u8 flags: bit0 advance by the engine clock, bit1 LOOP (wrap to 0), bit3 cleared on wrap
+0x04 u16 delay counter (0xFFFF = none), compared with +0x40
+0x08 u32 P919(clip name)
+0x0C u32 current key index (key / (keys-1) tracks time / duration within 0.02 on all 4 player trackers)

+0x14 f32 weight (copied into the job entry, 0x175F04)
+0x18 f32 sub-millisecond remainder
+0x1C u32 time ms
+0x24 i32 weight-set index, -1 = whole body (LEAD: 0x1B0EE4 indexes a 0x38-byte set array with it; NOT the member index)
+0x28 f32 second job float (0.01 base, 0.0001 clips) - LEAD
+0x44 u32 key count
+0x4C u32 duration ms == clip record +0x78 in 100 / 100

In play (MEASURED 2026-10-28, game focused; anim_watch(seconds=20), world clock 19,992 ms)

80 characters, 369 sample rounds at 50 ms. The motion LEADs above are settled: - Tracker time (+0x1C) advances at the world clock's rate: median 1.0 ms per world ms over 42,123 consecutive same-clip pairs (p10 0.75, p90 1.317 - blend-in / rate-scaled clips), 731 loops or restarts. So +0x1C is the clip's playback position in milliseconds, driven by the world clock. - The state slot changes as the character moves: 60 distinct state transitions, e.g. Idle -> IdleToRun (16), IdleToRun -> RunToIdle (17 + 11), Run -> Stumble (12) -> Run (9), Idle -> Wpn_Sheathe (10), Idle <-> AutoPicker_Fidget (8 / 8), RunToIdle -> TurnToRun (8). - 40 clips entered in 20 s (Orc_R_Hand_Weapon 57, GInf_Base_Idle 41, GInf_Combat_Idle 39, gDef_Combat_Idle 35, GInf_Combat_Idle_2_Run 22 ...). - Slot char+0x11A8 is either null or equal to the state +0x11B0: 29,520 / 29,520 samples (null in 10,540). It never held a different state while one changed, so it is not "previous state" (LEAD: a "state confirmed / entered" mirror). The meaning of +0x1198 / +0x11A0 stays open. - The pose job 0x1B0EE4 also runs on the MAIN thread in play (2.7% of MainThread samples, where it shows as an outermost frame: LEAD, the main thread drains the anim job queue as 0x7042FC does).
