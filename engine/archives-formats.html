Anvil — Offline Persistent Mod Engine (tools/anvil/)

2026-10-19 — ANVIL NO LONGER WRITES THE INSTALL. apply=True / install / asset_replace and every other write into a game archive is REFUSED (refused + why in the result; the edited GADB blob is still saved to tools/anvil/data/extracts/), modkit.install / set_mounted(on=True) refuse, and call("restore") goes through the Vanilla Guard. .vanilla IS NOT PROOF: MEASURED 2026-10-19, Patch_02.arch06.vanilla and Patch_02_LC.arch06.vanilla are NOT Steam's bytes while the live Patch_02 files are, so the old restore (copy every .vanilla over its archive) would have installed two modified archives. The text below describes the retired disk route and stays as its record.

Anvil is the disk-side counterpart to AIRE: it modifies on-disk .arch06 archives so changes persist across game restarts. No game running required for bake/apply. Vanilla .arch06 backups are created automatically (one-time, never overwritten).

Architecture: engine.py (orchestrator), archive_router.py (71-archive index), delta.py (plans), headless.py (AI-native JSON API), packager.py (.sowmod ZIP), snapshot.py (live capture), randomizer.py.

AI Integration: ALL operations go through tools.anvil.headless.call(action, **kwargs). Returns {"ok": bool, "action": str, "data": {...}}. No argparse, no printing.

from tools.anvil.headless import call

# ── Discovery (uses cached index, instant after first scan) ──
call("info")                          # game dir, archive count, records owned
call("list_archives")                 # all 71 .arch06 files
call("categories", filter="Combat")   # search 2,742 GADB categories
call("list_records", category="AI/SpawnAmbient/AITypes", filter="caragor")
call("show_record", category="AI/SpawnAmbient/AITypes", record="Enemy_DifficultyAny")
call("show_category", category="Faction/Events/SimEventChance")
call("find_spawns", match_template="Caragor")  # find all slots using a template

# ── Offline Bake (NO game running needed) ──
call("bake", preset={
    "aitypes": {
        "Enemy_DifficultyAny": "Werewyrm_talion",  # slot -> template
        "Enemy_Caragor": "Fellbeast",
    },
    "lists": {
        "World_Desert_Day": ["Goblin", "Werewyrm_talion"],  # bundle slot1, slot2
    },
    "fields": {  # raw u32 writes to any record field
        "Client/PlayerMovement": {
            "PlayerMovement": {"16": 46}  # field[16] = 46 (speed)
        }
    }
}, apply=True)  # apply=True writes to archives immediately

# ── Swap Spawn (targeted creature swap) ──
call("swap_spawn",
     match_template="Caragor",
     new_template="Werewyrm_talion",
     force_load_bundle="Werewyrm_talion",
     apply=True)

# ── War Mode (multi-creature chaos) ──
call("war", name="mythic_war", apply=True)   # built-in preset
call("war", name="boss_chaos", apply=True)   # Nazgul+Drakes+Trolls+Shelob everywhere
call("war", bundles=["Nazgul_base", "Fellbeast", "Troll_base"],
     bundle_slot="both", apply=True)          # custom mix

# ── Omnispawn (broadcast one creature/bundle globally) ──
call("omnispawn", bundle="Nazgul_base", bundle_slot=2, apply=True)
call("omnispawn", template="Werewyrm_talion", apply=True)

# ── Mount Swap / Field Edit / PRFB redirect ──
call("swap_mount", old_creature="Caragor", new_creature="Werewyrm", apply=True)
call("field_edit", category="Faction/Events/SimEventChance",
     record="Arena", field_idx=0, value=0x3F000000, apply=True)  # StartChance=0.5
call("find_prefab_refs", pattern="caragor")
call("redirect_prefab", source_pattern="caragor", target_pattern="werewyrm", apply=True)

# ── Packaging & Restore ──
call("bake", preset={...}, package="my-chaos-mod")  # creates .sowmod ZIP
call("install", sowmod="path/to/mod.sowmod")
call("restore")  # back to Steam's bytes via the Vanilla Guard (SHA-1-checked sources, quarantine)

Read-only GADB index actions (ADDED 2026-08-02, feed AIRE's correlation spine):

call("gadb_category_index")                    # ORDERED category array = the RecordLink index
                                               # space. `categories()` sorts by NAME and destroys
                                               # the ordinal RL is built from — use this instead
call("gadb_record_values", category="AI/Perception")   # raw shipped value cells per record
call("gadb_strings", offsets=[12345, 67890])   # decode string-block offsets

These are reads. They exist so AIRE can diff shipped-vs-live and key records by RecordLink; they never touch a write path, per the standing Anvil read-only rule.

Built-in War Presets: mythic_war, boss_chaos, beasts_unleashed, ringwraith_siege, troll_army, spider_invasion. Use call("war_presets") to list.

Archive Priority — WARNING: CORRECTED 2026-08-03 from the shipped x64/default.archcfg, which ends with "file search order is from the bottom up" and lists Global.Arch06 and HotChunk.Arch06 after every Patch_*. Bottom-up therefore makes hotchunk the HIGHEST priority GADB, not the lowest — the reverse of the long-documented Patch_04_LC > ... > hotchunk. Confirmed by content: merging all 25 GADB-bearing archives in archcfg order changed 0 existing values and only ADDED 1,996 that hotchunk leaves unset. Read the archcfg; do not hardcode an order. (tools/anvil/modkit.py still states the old order, premised on "the shipped order puts the patch archives last" — that premise is false for this file. Anvil is read-only by standing rule, so nothing is at risk today, but its routing assumption is wrong.)

RecordLink helper: RL = (category_index * 16) << 16 | record_index — Anvil's substrate exposes make_recordlink(cat_path, record_name). GADB parse/rebuild/expand/repack (Oodle Kraken) is handled internally by Anvil's substrate — drive it via call("bake"/"field_edit"/...); touch the substrate only when extending Anvil itself.

Packet -> Archive Mod Converter (PROVEN IN-GAME 2026-08-15)

2026-10-19 — THE ARCHIVE LANE IS OFF (game files stay vanilla). Ltar::SetMounted(on=true) and the menu's archive mount refuse (kArchiveMountingOff), and sow_packet_convert.cpp builds no archive (kArchiveLane = false): every asset goes to the live .hotswap sidecar, which writes nothing into the game. Taking a mount line OUT still works. The measurements below stay as the route's record.

The community's Find/Replace packet mods convert into archive mods — natively, in the DLL, no Python — so anyone with the shipped drop has the capability. Proven in-game: faceless Talion renders in full from the converter's two outputs with the original packet disabled; menu background + loading icon likewise.

A packet splits PER ASSET, and the split is provable, not a preference:

asset class route measured
has a LOOSE archive entry minimal .Arch06 (permanent, zero runtime cost) Faceless: 10 assets -> 839,177 B
container-only .hotswap live sidecar (instant toggle, slice revert) archive equivalent = 2,636 MB for ONE 1,941 B material
no stored form (decoded DDS) sidecar only branding: not TEXR-76, not a mip — measured 0/16

The sidecar is a STANDARD packet folder in Mods\<mod>.hotswap; Mods\ is a packet root in sow_hotswap.cpp, so the proven intercept engine serves it with no new format. Which side is cheaper is per packet — convert_packet reports both prices. Alternates (a Find that lost its path contest to a higher-priority copy) are an OUTCOME, not a failure.

Native modules (framework/sowframework/packets/): sow_ltar.{hpp,cpp} — TOC read, structural full paths, minimal authoring, SetMounted (BOM refusal, one-time backup, main-block insert, >512-file refusal); sow_packet_convert.{hpp,cpp} — Convert button, auto-mounts by default (a built-but-unmounted archive is correct, verified and INERT); sow_mod_shrink.{hpp,cpp} — Shrink button on clone cards. Needs nothing bundled: Oodle is the game's own already-loaded oo2core_5_win64.dll (one-arg GetCompressedBufferSizeNeeded — probe, don't assume) and the P=919 LUT is read from base+0x1DB50D0 with a sanity check. Python twins: tools/anvil/minimal_archive.py, aire/formats/packet.py (THE one packet reader). Cross-check law: native and Python must produce identical output (Faceless: 839,177 B / 15 files / 10+7+1, byte-identical both routes).

Clone shrink (call("mod_shrink", clone=...) / Shrink button): a clone mod is GB of ballast — measured, a 293.4 MB clone changes 3 files and rebuilds to 2.6 MB (112.5x), content-diffed (size diff scores ZERO on same-size swaps) and re-verified against the clone's bytes. Mount-slot law: no global mount cap observed (89 active archcfg entries run fine), but a clone SUBSTITUTES for its original's single line — N clones of one archive = N-1 silently inert — while a minimal archive INSERTS and coexists. Shrinking is the bypass.

Archive-writer law (IN-GAME 2026-08-15): chunk headers are 4-byte aligned relative to the blob start; the engine walks by that alignment and never scans, and OUR readers scan forward so read-back verify is BLIND to the one defect that hangs the loading screen. Every writer pads and gates on the strict engine-model walk (_strict_walk_failures / Ltar::Author) — first multi-chunk authored entry (19 chunks) launched clean.

Archive-writer law 2 — files inside a folder sorted by lower-case leaf (IN-GAME CONFIRMED 2026-10-07): the engine finds a file by BINARY SEARCH over its folder's file list, and every shipped archive keeps each folder sorted (ui_assets 278/278 folders, Patch_DLC3 773/773, highmip 1,168/1,168). All three writers (aire/armory/ltar.py, tools/anvil/minimal_archive.py, native Ltar::Author) sorted folders but kept files in INSERTION order, so an archive mounted, read back byte-perfect, and still hid files from the game: the Armory archive hid 56 of 97 (its blade's mesh / skel / material / colour texture) = the "invisible blade"; the 2026-09-02 build hid its 4 textures = the blade that "rendered black" (wrongly blamed on TEXR header naming). A by-name binary-search simulation predicted 12/13 live resource states (the 13th a streaming tier). Fix: sort (manifest first), refuse any archive where lookup_misses() is non-empty. User screenshot: the blade renders after the rebuild. Other writers' outputs passed only because their callers happened to pass sorted lists. Audit any archive with ltar.Archive(p).lookup_misses().

Conflict pre-flight (Python-side): call("mod_conflicts") — four checks (slot / path / shadowed / live-signature), all presenting in-game as "nothing happened"; call("mod_can_enable", mod=...). Not yet native. The Python container lane (containers=True) is also Python-only — the 71 MB section index matters ONLY there; default-config output is byte-identical without it.

Index-space trap: aire EntryIndex row i = minimal_archive.ArchiveToc entry i+1 (the substrate APPENDS the recovered file #0). Join only via size-verified toc_index_for() — a raw join priced a 2,636 MB container at 84 KB.

Archive & Format Knowledge (backs Anvil + aire.formats)

Archive Layout (DECODED 2026-04-23)

71 .arch06 archives total. Priority order: Patch_DLC > Patch_XX > base.

hotchunk.arch06 (62.2 MB, LTAR v4, 47 entries):

  • Entry[0]: archivepatchloosefiles.txt = THE GADB (56,759,100 bytes, raw GADB, no Firebird container)
  • Entries[1-28]: database + database\string pairs (14 pairs, SKDB v9 format, per-region string overrides)
  • Entry[29]: database\string\zhcn (88 bytes)
  • Entries[30-46]: database\string\globalresources_*.bndl (17 per-language string bundles, 136 bytes each)

global.arch06 (7.9 MB, 243 entries): rendering materials, shaders, FX only — NO GADB. corecharacter.arch06 (208.7 MB, 77 entries): character .bndl manifests + .embb data bundles. Oodle DLL: x64/oo2core_5_win64.dll (Kraken codec, ships with game).

BNDL v6 Format (CORRECTED 2026-08-06 — byte-identical emit 1,276/1,276)

.bndl is the manifest for the paired .embb, and it MIRRORS it: same path table, same path offsets, and the same payload-size array the EMBB carries as size prefixes.

[0x00] "BNDL" magic
[0x04] u32  version (6)
[0x08] u32  path_table_size                     == the paired EMBB's
[0x0C] u32  path_table_size + align4(len(type_string)+1)
[0x10] u32  asset_count                         == the paired EMBB's
[0x14] asset_count × u32  PAYLOAD SIZES  ← identical to the EMBB's size prefixes
[0x14 + ac*4] path table (path_table_size bytes) — identical BYTES to the EMBB's
[after path table] "Bundles/Types:XXX" null-terminated, then 4-aligned
[then] asset_count × u32 path offsets — identical to the EMBB's

[0x0C] is NOT [0x08] + 28. That held on 995 of 1,276 sampled manifests and failed on 281 (deltas 20/24/32/36/40). The rule is [0x0C] = path_table_size + align4(len(bundle_type)+1) — i.e. the combined length of the path table plus the type string region — which holds 1,276/1,276. Emitting the constant 28 produces a corrupt manifest for ~22% of bundles.

Bundle types are open-ended, not a fixed three: Presentation (208,575), WorldQuest, Sound_1, FlairWorld, Flair_1MB, WorldLighting, ThroneRoomBarrows, UI_Tutorial, QuestCinBundle, … — read it, do not assume it.

RESOLVE THE MANIFEST FROM THE EMBB'S OWN ARCHIVE. Looking up the .bndl path independently crosses a patch boundary: a bundle updated by a patch ships its EMBB in Patch_* while the base archive still holds the ORIGINAL manifest. Measured on 40 shipped character bundles, 3 paired that way and disagreed — player_rhovaniont2_cloak matched on all 11 paths but declared asset 2 as 87,657 bytes against the patched EMBB's 43,961; orc_buff_leather_pants_g paired a 4-asset EMBB to a 3-asset manifest from a different archive. Cortex._embb_manifest takes the neighbouring entry in the EMBB's own archive and confirms it by CONTENT (identical path list) before trusting it — 60/60 after the fix, and the one bundle with no confirmable manifest is reported as such rather than silently paired to the wrong one.

A PATCH CAN UPDATE ONE ASSET OF A BUNDLE BY MANIFEST + LOOSE FILE (MEASURED 2026-10-09). Patch_DLC4_LC re-ships the defender_weaponpairs\*.bndl manifests WITHOUT their EMBBs (those win from ui_assets). Paths identical; one size differs: orc_metalshield.skel is declared 147,990 while the ui_assets EMBB carries 128,871, and 147,990 is exactly the LOOSE orc_metalshield.skel in Patch_DLC4/_LC. So the vanilla pair the engine loads is cross-archive by design (that the loose skel is what gets used is a LEAD, not observed at runtime). Reading a pair for ANALYSIS: own archive (above). SHIPPING an override: start from the WINNING manifest and change only your own slots; rebuilding it from the EMBB would undo the patch's declaration.

SKDB v9 Format (CRACKED 2026-04-23)

Serialized Key Database — per-region/per-language string override tables.

[0x00] u32 magic "SKDB"
[0x04] u32 version (9)
[0x08] u32 header_size (28)
[0x0C] u32 key_count (total hash entries across all language sections)
[0x10] u32 reserved (0)
[0x14] u32 string_pool_size (byte size of the UTF-16LE string pool at EOF)
[0x18] u32 reserved (0)
[0x1C] u32 lang_count (19)
[0x20] lang_count × (u32 section_data_offset, u32 cumulative_metric)
[after section table] Initial key lookup table: 8-byte entries
[at each section_data_offset] Per-language key lookup tables: 8-byte entries
[EOF - string_pool_size] String pool: flat, null-terminated UTF-16LE strings

Each 8-byte key entry: u16 hash_lo, u16 hash_hi, u16 secondary_hash, u16 string_index (string_index = 0-based index into the flat string pool). Access via aire.formats.StringEditor.

EMBB v5 Format (RE-CRACKED 2026-08-06 — THERE IS NO PADDING)

aire/formats/embb.py; call("embb_probe" / "embb_verify" / "embb_replace"). Offline. Full write-up: aire/documents/EMBB_BNDL_CONTAINER.md. Byte-identical rebuild from parsed parts 400/400 — the only standard that counts.

Population verified COMPLETE (not sampled): 190,407 EMBB blobs, 100% version 5 and 225,311 BNDL blobs, 100% version 6 — no version variants exist. Header + path-table invariants pass on 190,407/190,407 = 100.0000%.

[0x00] u32 magic "EMBB"
[0x04] u32 version (5)
[0x08] u32 path_table_size
[0x0C] u32 asset_count
[0x10] path table: asset_count NUL-terminated ASCII paths, each NUL-padded to
       a 4-byte boundary.  path_table_size == end of the last aligned path, EXACTLY.
[0x10 + pts] asset_count × u32 — byte offset of each PATH, relative to 0x10.
       This is a path index, NOT a section table.
[then]  asset_count × [ u32 payload_size ; payload ]
       payload begins with its own 4-char tag, chosen by the path's EXTENSION.

Measured over 964 containers / 35 archives / 8,218 sections (all version 5):

invariant result
chain terminates exactly on EOF 964/964, slack 0
path_table_size == end of last aligned path 964/964
path offsets 4-aligned and chained by aligned length 964/964
zero-size / oversize sections 0 / 0
byte-identical rebuild 400/400

THERE IS NO PADDING AND NO ALIGNMENT IN THE SECTION CHAIN. A payload is followed IMMEDIATELY by the next section's u32 size prefix. Section start offsets mod 16 are ~uniform (0: 8.9%, 7: 4.9%, 15: 5.7%) and only 531 of 964 containers have every section 4-aligned — player_celebrimbor_armor_pc.embb itself has sections at mod-16 of 7, 13, 5 and 1. So a payload may be ANY size; nothing is rounded up, and there is no slack to preserve. Do not pad a resized payload — padding is what would be wrong.

THE OLD READER'S TWO ERRORS. It read asset_count + 1 offsets, but the (count+1)-th u32 is the size prefix of section 0, not a table entry — so section_data_start was 4 bytes past the truth and the last "offset" (27,928 on that bundle) was misread as "total size of dependency data". Sections were then located by scanning for known tags, which cannot work: a 4-byte tag occurs by chance inside texture and mesh payloads (18 tag hits for 17 real sections on one 12 MB character bundle, several deep inside TEXR data), and sizes came out as "distance to the next hit". Those sizes are fiction, and they are why the container appeared to have padding. The substrate parser was repaired 2026-08-06 — it now walks the chain, so asset_probe/asset_decode/export_obj and every other caller are correct too. It falls back to the old scan ONLY when the chain is broken, and then reports chain_valid: false and refuses to rebuild rather than writing guessed sizes.

Extension → tag (8,218 sections, none contradicted): mesh→MMSH, skel→SKEL, anix→ANIX, tex→TEXR or SLVT, texa→TEXA, texcpu→CPUT, mat→LTMI, fxo→SRHR, fxp→LTFX, inst→PRFB, bnk→BKHD, cres→CRES, vid→VIDO, subb→SUBB, wldmsh→MESH, objres→OBJR, uis→UISH, uiwd→UIWD, scripts→SCRI, wldclnt→WDSC, hkai→HKAI, veggrid→VEGG, terrain→TERR. (CDEF is not a tag — see the phantom-tag note.)

WHAT ACTUALLY BREAKS A RESIZE — three things must move together:

  1. the resized section's u32 size prefix inside the EMBB;
  2. the matching entry in the paired BNDL's size array;
  3. the archive entry's uncompressed size (Anvil/modkit).

Splicing a bigger payload in place without (1) leaves the loader reading the next section's size from inside the new payload. Reproduced exactly on player_celebrimbor_armor_pc.embb: a +1,500,000-byte MMSH splice makes section 9's size read as 0xAAAAAAAA = 2.86 GB, which the streaming loader then tries to consume — that is a hang on load, and it is indistinguishable from a geometry failure unless you walk the chain. EmbbContainer.parse refuses such a file with the offending section named.

Behaviour graphs (.bvr) - animation state machines, decoded node by node (MEASURED 2026-10-27)

A .bvr is a GADB v17 database (root BlendDB): categories = node types, records = nodes, mostly NAMED SECONDARY records (CORRECTED 2026-10-27: not anonymous primaries as the 2026-08-05 behavior.py read). 29 graphs, 10,702 blend states, 73,448 transition links; player graphs (player_elf / el2 / elt / bar) ~2,050 states + ~1,700 camera states each, orcs ~132, warg 431, troll 218.

  • Links: 73,017 resolve to a decoded state, 431 have no target, 0 name a missing state.
  • 5,300 states (49.5%) are reachable by transitions from the start state; the rest are entered BY CODE (grabs Grab_HOG_* / GrabFlurry_*, warg riding, ladder climbing, mount deaths) - the states sync actions and presentations force.
  • Clips: 17,606 / 17,606 state clip references resolve to an ANIX carrier (archive, entry, clip index, P919 hash); invented names resolve to nothing (control). The .skel set paths the nodes name ship nowhere: the join goes through the ANIX clip directories.
  • Field readers are thin (17 fields) because a BlendDB record is a NATIVE STRUCT (header +0x01 = 0x1A on 318,372 / 318,372 live records): fields at instance + SlotOffset, read as plain members. Live offsets checked 10,697 / 10,697 (behavior_field_offsets, behavior_live_node; kb/gamedb-schema.md slot-law exception).

Actions: behavior_graphs, behavior_graph, behavior_state, behavior_moveset, behavior_clip, behavior_field_readers (aire/formats/behavior_actions.py); full reference aire/documents/BEHAVIOR_GRAPHS.md. Edits are LIVE record writes, never the file.

Havok tagfiles - navmeshes and physics shapes (aire/havok/, VERIFIED 2026-10-27)

  • Census (havok_tag_census, cached): every carrier parses EXACTLY, 0 parse failures, all types consistent across files - standalone .hkai 923 files (185 types), EMBB HKAI sections 1,176 files, OBJR-entry physics 5,148 files (196 types), EMBB OBJR physics 4,808 files.
