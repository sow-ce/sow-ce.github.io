Threads (MEASURED 2026-10-28)

From kb/live-runtime.md "Threads and the frame" (not re-measured): Wwise threads have no engine name; AK::EventManager (creator 0x1310C10, the audio render thread), AK::BankManager (vt_0x22D65D8 vf1 0x1312008), AK::IOThread (0x132E474, streaming), "AK Suspended" (0x1309C78). GameAudioMgrThread is a KRAKEN thread (routine 0x181F638, below). Bink: 5 threads inside bink2w64.dll, started by BinkStartAsyncThread from the render-side init 0x1CB60C0 (via 0x1CD21A0; BinkSetMemory there too); Bink's own audio output is set up there as well (BinkSetSoundSystem2 + BinkOpenXAudio2, 0x1CD22AC); 0x1CB6194 stops the async threads and frees the Bink globals (BinkRequestStop / WaitStopAsyncThreadsMulti, BinkFreeGlobals). VideoClipRequestThread (routine 0x11C7488 -> 0x11C7274) is an event-driven request loop whose purpose is NOT established (Open leads).

The Wwise library inside the exe: globals, queue, message types (MEASURED / LEAD 2026-10-28)

Banks are BKHD version 118 (6 / 6 sampled, init.bnk included) = Wwise 2016.1 (LEAD: version-to-release mapping from public bank tooling). Load path (MEASURED, code). A bank is a KRAKEN resource: the bank loader vt_0x22C3850 vf4 0x54FEA4 gets the file bytes, builds a 0x18-byte handle {+0 u32 bank id (out), +4 u32 size, +8 data, +0x10 byte "not init.bnk", +0x11 byte "not _Metadata"} and calls sound manager vf32 0x54FF78. vf32: under the bank lock, banks that arrive before init.bnk are parked (+0x70); init.bnk loads, then the parked ones. 0xC378A0 loads one: size >= 0x14, BKHD +0x10 language id must be 0 or [0x270347C] (other-language banks are refused), then 0x12F1A00(data, size, pool [0x25D6F80], &id) (copy into a Wwise pool) or 0x550088(data, size, &id); result 1 = AK_Success -> handle+0 = bank id.

Live bank list (MEASURED 2026-10-28). CAkBankMgr [0x26FF9B0] +0x90 = hash table {buckets*, u32 n (97), u32 cap, u32 count (83)}; bucket entries point at bank slots (vt_0x1DBAA38): +0x10 u32 bank id, +0x18 data, +0x20 chain next, +0x38 u64 size. 83 / 83 bank ids named from the bank index; 210.2 MB (kb/binary-code.md's heap census: 70 BKHD allocations, 216 MB). Largest: global_ui 26.7 MB, wraith 25.9, cbt_insta_chordkills 13.2, wld_glb 13.0, mus_global 12.4, char_troll_glb 10.8, cbt_player 10.5. Control: 51 / 83 slots' data pointer still points at a BKHD whose id equals the slot id; the other 32 point at reused memory (the source buffer is freed after a copy load) - never dereference +0x18. The other two tables in the bank manager: +0x78 (12,289 buckets, 8,775 items: media, LEAD) and +0xA8 (29 buckets, 4 items, unknown).

GameAudioMgrThread (MEASURED 2026-10-28, code)

Started by 0x178C98C when byte [0x266D9D9] != 0 (live 1): KRAKEN thread with routine 0x181F638 on the object at [owner+0x127DB8]. The routine registers with an engine service (engine vf15 -> vf1), then loops 0x6AB618(worker [arg+0x38], &worker+0x38) - a JOB loop (runs queued jobs until worker+0x120 is set) - and unregisters. 0x178C98C also posts the first job, 0x181F704 -> 0x181ED58 = the AudioHooks compiled-cache rebuild (memory nemesis-death-memory-dialogue.md), then reads AudioHookList. Mod routes and traps (LEAD 2026-10-28)

  • Play any shipped event on any emitter: emitter play 0x3AD6A8 / sound manager vf13 on the MAIN thread (string name, FNV-1 resolves it). The bank holding the event must be loaded (live list above; wwise_event_find names the bank); the streaming bank system loads banks by event-name prefix.
  • Per-object cap 50, global object cap 725: a mod that spams events on one emitter is silently refused.
  • New VO = an external source: a dialogue line is a generic event + a Vorbis file name resolved by the IO hook in External*.pck. A new line needs a file the IO hook can find (not attempted).
  • Banks of another language are refused at load (BKHD +0x10 vs [0x270347C]).
  • Movies: an Interface/Movies record's path points at .vid, the file is .vib; 214 records point at files that do not ship (cut UI clips) - repointing such a record's Movie at a shipped clip is a data-only lever (not tried). Loose .bk2/.bik/.mp4 playback exists in code but is gated off (byte 0x2A37714 = 0).
  • Every audio write lands on the Wwise thread's data: AudioHooks are compiled at load (CLAUDE.md law on hot-thread GameDB domains), and bank memory is shared - read only.
