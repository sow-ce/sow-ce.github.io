Captain body roll - the seed and the CLASS decide the body (MEASURED 2026-10-08)

A captain's body type is NOT random per rebuild and NOT what the FM body slot says: every model build rolls it from his seed and his class. Static disassembly + a live check: predicted body type equal to the built one (SMC+0x00) for 144/144 living captains (aire read-only script).

RebuildDirect 0x1BC3AA8(fm): params 0x577190, 0x1BEA190(params, fm), 0x4C5194(FM+0x2D8, params)
0x1BEA190  params+0 = FM+0x168 (u64 seed); params+0x250 = Unit(Lcg(seed)) + 0.0 ("scale");
           params+0x210 = FM+0x278 (class, Character/Models); +0x228/+0x238/+0x240 = FM+0x270/0x318/0x268
0x4C5194   SimpleModel = Character/Models.SimpleModel (else params+0x218); entry = 0x6A9F38(...);
           SMC+0 = entry.BodyType; head = 0x2EDBB4 = a pick from the ENTRY's DynamicHead list
0x6A9F38   per SimpleModel.Models entry: weight = BodyWeights[j] of the LAST RequiredScaleRange[j]
           (float-pool pair) with lo <= scale <= hi; no match / Body.Model NULL -> skipped;
           reservoir 0x1B3B90 on a COPY of the seed: weight <= 0 -> no draw, else
           s = Lcg(s), r = Unit(s) * (acc + w), pick when w > r, acc += w
Lcg(s) = s*0xBB38435 + 0x3619636B; Unit(s) = float((s >> 32) / 4294967295.0) - the size-roll LCG

The seed decides the whole look, and the engine calls it random_seed (MEASURED static 2026-10-17). The orc exporter 0x1BC5044 (Vendetta / Conquest publish) writes FM+0x168 under that key. In 0x4C5194 the same params pick the HEAD 0x2EDBB4 (the body entry's DynamicHead list, weighted 0x36B2F8 -> reservoir 0x1B3B90; params byte +0x254 = only heads whose bundle is available, 0x2EDDFC - RebuildDirect leaves it 0: 0x577190 clears it, 0x1BEA190 never sets it), the HAIR 0x6C8BB4 (that head's own hair list, when SimpleModel.CanApplyHair) and every COLOUR 0x2E9A2C from the class SimpleModel's colour setups: SkinTint, EyeTint, HairTint, TattooTint (+TattooChance, TattooMaterialOverrides), PaintTint (+PaintChance), Armor/ClothingTint, Trim, Faction* -> Model/SimpleModelColorSetup -> _StructuresSimpleModelColorEntry {SelectionWeight, Hue, HueDeltaRange, Saturation/Value Min/Max, AppearanceTag gate}. A face, hair or skin colour written before a rebuild is therefore overwritten by the seed's own pick (24 of 25 catalog heads of a 2026-10-17 roll never stuck). The native lever for a new face + matching hair + native colours is a NEW SEED before the rebuild (randomizer Config::nativeLooks, built, NOT run).

Class entries (Model/SimpleModel, MtnPass session): Defender Buff 0.3 [0,0.6] / Slim 0 / Stocky 1 [0,1] (Buff for ~14% of seeds); Infantry Buff 1 [0.3,0.7] / Slim 1 [0,0.33] / Stocky 1 [0.67,1]; Berserker Buff 1 [0,1] / Slim 0 / Stocky 0.15 [0.6,1]; Spearman and Archer Slim 1 [0,1] / Buff 0.15 [0.3,0.7] / Stocky 0 or 0.01; OlogHai_Infantry Olog only; Easterling_Infantry body type 12. Consequences: a body transplant never survives the rebuild; changing a captain's CLASS re-rolls his body (a Pretender made a Defender came out Stocky on the next rebuild - Norsko, Ugakuga); a non-orc class gives a non-orc body AND head (Bubol, an orc given Easterling_Infantry by a roll, rendered with an Easterling head his region never loaded). Scar / Machine bodies come from ITEMS applied after the entry body.

ONE seed copy, in order - why a class change gave a new FACE (MEASURED 2026-10-18, listings). 0x4C5194 copies params+0 to [rsp+0x78] once and passes that one copy to the body roll 0x6A9F38, then the head 0x2EDBB4, helmet 0x701A98, hair 0x6C8BB4, colours 0x2E9A2C, accessories 0x6F4CA4/0x6F5614. The body roll moves it one LCG step per entry that DRAWS (matched range, body model, weight > 0), so a class table drawing a different number of times shifts every later pick. The class kit's appearance tag (Faction/AppearanceTags/Setup/Orc_Defender = Tag_Defender) is set before the copy is taken (0x576FFC -> params+0x248 -> 0x1C06064).
