The slot word is the re-roll mask (MEASURED static 2026-10-28)

Slot entry (FM+0x1E0, 0x20 each): +0 picker, +8 trait, +0x10 unlocked trait, +0x18 u16 flags, +0x1A i16 option. The u16 at +0x18 (copied from FactionSystem+0xE0 per picker when the slot is added) is two things at once:

  • the gate list - 0x1234E0(&slot+0x18, bit) (bt) decides which tests the resolver runs: bit 1 level, 2 row rank, 3 follower, 4 required traits, 6 intel, 7 campaign predicate, 8 difficulty;
  • the re-roll mask - the resolver 0x3528C4 first ANDs the rebuild's reason mask with it and, when the result is 0, returns slot+8 untouched: 0x352AB8 is xor eax,eax; cmp word [rcx],ax; sete al. So a slot is re-decided only by the events whose bit it carries.

The rebuild 0xF88230 (UpdateTraits 0x3528A0(fm, reason)):

mask = 1 << reason                                   (0xF885E3 bts)
if FM+0x508 bit 34: sort the slots, clear bit 34     comparator 0x7127A8: Picker.SortPriority,
                                                      higher first, ties by address
reason 0: active set emptied (FM+0x1A0 = FM+0x198), FM+0x378 = 0, FM+0x508 bits 14 / 19 cleared,
          byte FM+0x51C = 1
per slot: new = 0x3528C4(slot, &mask, &ctx)
          if new == old and reason != 0: skip
          mask |= bit 4 (a trait changed: required-trait gates of later slots re-run)
          0x353454(fm, old) deactivate, 0x3566B0(fm, new) activate

Every picker of the live table has bit 0 (MEASURED 2026-10-28: 493 / 493, none with flags 0), so reason 0 (every reward, every save load) re-rolls every slot, as recorded before; reason 1 / 6 / ... re-roll only slots gated on that event. Live control (553 pool entries, 19,713 slots, one save): no slot has +0x18 == 0, so "flags 0" marks a custom slot with no false positive.

Slot +0x10 (CORRECTS the memory's "forced-trait filter" reading, 2026-10-28): it is read only for options with MissionUnlock_MinXPLevel != 0: such an option passes when his level is at least the remapped MissionUnlock - 1 (0x352DB8) AND its trait equals slot+0x10 (0x3529A3). It is the trait a story mission unlocked for that slot. The planner treats MissionUnlock options as failing, which holds while +0x10 is 0 (MEASURED: 0 of 19,713 live slots have it set).

Option walk the resolver uses (also callable for a lookup): 0x352BB8(&iter, picker) (Picker.Traits, iterator 0x30 bytes: +0x28 index, +0x2C count), 0x352B2C(&iter) = the entry at the index (through System::ApplyFactionTransform), 0x352AC4(entry) = its Trait, 0x2774A8 = at end.

Evidence: listings of 0x3528C4, 0x352AB8, 0x1234E0, 0xF88230 (the loop at 0xF88610), 0x7127A8, 0x352BB8, 0x2774A8, 0x352AC4. Static only.

Custom slots and fm forcetrait (BUILT, NOT RUN 2026-10-28)

A slot {picker, trait, +0x18 = 0, option} is never re-rolled: the resolver hands back its trait for every reason, and the reason-0 rebuild deactivates and re-activates it like every slot, so the engine's own activation gives everything the trait gives (items, gang cache, derived FM+0x508 bits, spawner hijack). It lasts until a save load: the loader re-adds the picker through 0x7CD03C, which copies the table flags back, and rolls it the game's way. A custom slot = flags 0 on a picker whose table flags are not 0.

User request 2026-10-28 ("anything can be given ... minus the beast contradiction etc."). The Army Grid > Traits menu has a Custom traits switch (on by default, session only). Verb fm forcetrait <fm> <trait> <picker> <replace picker> <replace trait> (sow_main_native.cpp RunFmForceTrait):

  1. the slot it contradicts (or his own slot of that picker) out: 0x353454 + erase 0x7A7378;
  2. the slot in through the loader's own add 0x7CD03C (no group / marker test), sort bit 34, UpdateTraits(fm, 0); if the game's roll gives the trait, done (a normal slot the save keeps);
  3. else the rolled trait deactivated, the slot written {+8 trait, +0x18 0, +0x1A option} (option = the trait's index from the resolver's own walk, which also proves the trait is that picker's option), UpdateTraits(fm, 0) again;
  4. kept only when the slot holds the trait AND it is active; otherwise the slot goes, the replaced slot is put back through 0x7CD03C, nothing changes.

Planner (sow_trait_planner.hpp): the game's route first when it is sure and replaces nothing; custom otherwise. Hard refusals on every route: class / advanced class / rarity slots, Quirk_Undead while he is in the world, 64 active traits, FM+0x508 bit 38.

Planner twin, read-only (MEASURED 2026-10-28, 30 seated captains, Difficulty_5Bloody): of 5,790 (captain, non-DLC card trait he lacks) pairs, the game's route gives 4,526; custom where the game's roll then gives it (only a marker or group stood in the way; the save keeps it) 391; custom forced 837; still refused 36 (27 Quirk_Undead counted as never addable by the twin, 9 "contradicts 2 of his traits").

Not checked in game: the activation of a forced trait, a forced gang / summon / hijack trait on a captain in the world, a forced trait whose items need a character type (0x355474 refuses the item), traits gated on a marker (Raise_Dead wants Marker_StatusEffect_Curse) doing anything, what a save load leaves.

Exclusive groups: contradictions and design limits (MEASURED 2026-10-28)

All 51 PickerGroup_* records (Picker.ExclusiveGroup) with their pickers' options, read live:

  • design limits (relaxed for custom traits): DLC4_Ultimate (10 pickers), DLC4_Opener (3), BodySlamThroatGrab (2), Mannerisms_Pool (23 audio mannerisms, not on the card);
  • one of a kind the engine keeps: GangOrPet (13; FM+0x378 caches the first gang leader), HasMount (2), ElementalWeapon (5);
  • a strength and its own opposite: Resist_Fire / Stealth / Poison / Ranged / Beasts / Combat / Grab (immune or resistant vs vulnerable or mortal, one element), every _Fear_Hate / _FearHate (fear vs hate of one thing; Caragor_Fear_Hate also holds Summoner_Caragors, PetCaragor_FearHate the caragor pets), BeastSlayerOrDismount (Monster Slayer vs Dismount Rider), AggressiveUnAgressive, LastChanceModifiers (Humiliator vs No Last Chance), RepositionMoveAway, VaultBreaker, BodyguardDefeat, HateBossDefeat, KillOtherCaptain, WeakByHate_PinningShot, Alone_Fear, Blocks.

The custom route still replaces the slot of a non-relaxed group (RelaxedGroup() in sow_trait_editor.hpp).

The card's text: markup and colour aliases (MEASURED 2026-10-28)

The localization strings carry the Scaleform card's markup (63,493 strings of the shipped table, aire MasterStringDB, read-only):

  • colour runs {Color_<Alias>}text</font>: Enemy 593, Player 498, Objective 305, Broken 46, Intel 43, Epic 35, Follower 16, Reward 6, Weakened 5, Green 2, Red 2, Hate 1. In trait NAMES only Epic (35 names, wholly wrapped: {Color_Epic}Epic Trait: Slayer Counter</font>; 36 of 484 trait records' Summary strings carry markup);
  • font runs <font face="$INTHUD">...</font> (51); glyphs / button prompts {Poison}, {CombatPrimary03}, {EpicSkull}; format arguments {1!s} {2!d}; voice cues <laugh> (dialogue).

A colour alias is a Profile/ActionAlias record (Color_Epic; GamepadString / KBMString / FontColor) whose FontColor links an Interface/Color record; its Color Int is ARGB, live: Epic 0xFFE24E2C, Red 0xFFA42E06, Green 0xFF359737 (Red / Green confirm the byte order). Color_Enemy / Color_Player also carry strings UI_Color_Enemy / UI_Color_Player.

Shared card names: 21 card names belong to 2-3 card traits each. Their record names' family words tell all 21 apart: Easterling / East, D4RES / DLC*, DEMO, Elite, Rare, Six, Archer, CMT (Combat Master), Perm, ET. Examples: Agile / Agile (Easterling), Decoys / Decoys (Elite) / Decoys (DLC six), Damaged by Executions (Combat Master), Immune to Curse (demo), Trapper (Easterling) vs the Tracker one.
