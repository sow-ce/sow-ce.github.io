Characters, the player and the camera

The character object and its key fields, the player, the camera pipeline and what the screen actually reads, near-camera dissolve, the character controller with its collision layers and trigger volumes, Wraith World and the wraith companion model, weapons and holders, runtime material slots, render IDs, mounts, and Talion's material controller.

The character object

Every character - the player, NPCs, creatures - is a CCharacter. AI characters have vt_0x1FB3640; the player is a CPlayerObj (vt_0x1F96818).

+0xA0 the body pose
+0xAC position, 3 floats in cm (Y up)
+0xB8 rotation, a unit quaternion (x, y, z, w); forward = q * (0, 0, 1)
+0xC8 scale
+0xE2 bit 0: visible
+0x110 the skeleton object; [[char+0x110]+0x1C0] is its model animation instance (see Animation)
+0x120 the behaviour-interface base subobject
+0x22E0 the face ([[[char+0x22E0]+0x60]+0x60]+0xA0 = the face pose)

The player is [base+0x2797808], the first entry of the player list [base+0x2A34C68]; the client shell [base+0x26FFA98] holds it at +0x888. Player-only fields: +0x2F10 AI-spectator invisibility, +0x2F88 the movement chain, +0x2F90 the camera / dissolve object, +0x2FA0 the combat component, +0x2FA8 vision mode, +0x2FC0 the scene component, +0x3420 the screen camera copy, +0x2578 the mount being ridden. A bone's world position comes from the pose and the bone hashes: a skeleton object's runtime skeleton [[[skel+0x10]+0x18]+0x10] holds +0x40 the bone count and +0x78 the bones' name hashes in pose order (Talion 128 bones, the face rig 241).

The camera

owner = [[[base+0x26FFAA8]+0x6CB0]+0x6728 + i*8]   (vt_0x1FD99F8; the local player's entry has +0xDEA8 set)
owner+0xDEA8 -> the camera modifier data (md)
owner+0x5F0  -> the modifier list (sentinel; +0x5F8 first node; node = modifier + 0x10, next = node + 8;
                modifier +0x08 owner, +0x20 its GameDB record, +0x28 state, 2 = finished or skipped)
md+0x66C position, +0x678 rotation quaternion, +0x690 / +0x694 horizontal / vertical FOV (radians)
md+0x650 / +0x688 the previous frame's transform / lens

A frame (0x2FC6B8): 0x51BF3C(md, dt) prepares from the previous camera and the focus; 0x51BCA8 runs each modifier's vf7 on md, validating after each; the finalizer 0x51BE7C stores the result into the output object md+0x768 (+0x3A4 transform, +0x3C0 start transform, +0x3F4 / +0x3F8 lens). The screen reads that stored copy, not the live md: 0x2FEA2C -> 0x51AC00 -> 0x51AC30 -> 0x4E0CFC copies it to player+0x3420, which drives the view, camera transitions and the lens. The live md is the camera's state for the next frame. The gameplay camera Camera/Behavior::Camera_Primary has 12 modifiers (Adjustables, Lens, SetRoot, SmootherBegin, Distance, OrbitControl, AvoidObstacles, Pitch, Yaw, Roll, Smoother, Collide); only the collision modifier (vt_0x1DB5FE0) calls SetCameraPos 0x51C394. Presentation cameras are the *_BS / *_BR modifier families.

The debug camera manager [base+0x2A86860] (vt_0x22F4A90, a state machine; built at client start by 0x17CD2EC, read by the screen copy 0x4E0CFC) takes a mode from DebugCamera.FreeCamControls (handler 0x17CFF54: "Cinematic", "ClipMode" or "Marketing" stored as 0 / 1 / 2 at +0x118). DebugCamera.Track (0x17D0074) follows a named object.

Near-camera dissolve. Camera/CharacterDissolve (34 records: hide and fade radii and lerps) is set by camera behaviours (setter 0x1567E8, controller +0x240) and by presentation elements (1,380 of 3,548 set Dissolve.Settings, controller +0x248). 0x6C4E60 builds two capsules from the camera along its forward axis; the classifier 0x30A368 -> 0x309128 -> 0x308BE0 returns show, fade or hide from the capsules against each body's capsules (a camera inside a body forces hide), unless the character's forced mode overrides it (3 volume decides, 0 always show, 2 always hide; set by presentations' HideActors / ExcludeActors and HideAllCharacters 0x19B43B4). The result drives the material constant k_fDissolve (0x3093F4); at 1.0 the visible bit clears. Every result reads one table on [player+0x2F90] (vt_0x1F67370): +0x258 show {0.0, 0.2}, +0x260 hide {1.0, 0.1}, +0x268 fade {0.76, 0.2}, copied once when the player is initialised.

The character controller

ctrl = [[[player+0x2F88]+0x08]+0x28] (the movement object vt_0x22F7738 sits on the way; one controller per character, 94 live in one scene). The controller is vt_0x1DB4DE0: +0x38 owner, +0x40 the hknpCharacterProxy (vt_0x1DBDA20: +0x3C filter info, +0x80 position in metres, +0xB0 velocity in m/s), +0x81 support state (2 = standing), +0xE4 collision filter, +0xEC gravity on. Slots: 5 SetPosition (cm), 6 SetVelocity, 8 Step (-> 0x399F18 integrate), 11 SetGravityEnabled 0x3F1900, 12 IsGravityEnabled, 13 refresh support, 20 SetCollisionFilter 0x3F14B4 (writes the controller's and the proxy's filter), 24 CopyFrom. The controller object is replaced during play (across a death or respawn), so it is reached through the chain on every use. The character controller's gravity (Client/PlayerMovement: -2000 at the movement object's +0x54) is separate from the rigid-body world's.

Collision layers. The world's collision filter is the object at [hknpWorld+0x480] (vt_0x22C2530, an engine subclass of hknpGroupCollisionFilter): two bodies collide when table[layerA] & (1 << layerB) (table at filter +0x24, symmetric). The player's proxy is on layer 7 (row 0x0030003D); every AI proxy is on layer 1 (row 0x00000001, the world only). Hit capsules use layer 6. Every character also carries a sensor body on layer 28 (filter 0x1C) exactly at its position. Trigger rows: 27 = 0x10000001 (layers 0 and 28), 28 = 0x48000001 (0, 27, 30), 30 = 0x10000001 (0, 28). The world's body array is [hknpWorld+0x28] (15,360 entries of 0xB0: +0x30 position in metres, +0x60 shape, +0x6C filter info with the layer in bits 0-4, +0x70 id); about 4,300 bodies are live in a region.

Trigger volumes. Script triggers are Havok trigger bodies: the trigger class table at 0x2A61E48 (TriggerSpatialBase constructor 0x1A52C88, TriggerSpatialShape 0x65575C / vt_0x1DC1228, TriggerSpatialDims 0x65599C / vt_0x1DC1660). TriggerSpatialDims vf45 0x3DAD68 creates the trigger through the physics system on layer 27 (31 for corpse triggers); TriggerSpatialBase vf21 0x3DA8AC filters by script tags, the player, excluded character types, mount and rider. Layer 27 meets only layers 0 and 28, so triggers react to characters' sensor bodies. The levels place out-of-environment kill and teleport volumes this way (for example OOEKillVolumes / OOEKV_* under Minas Ithil and the fortress walls' *.OOETSS / *.OOE_SO script objects, which teleport the player back): a character under the world dies by trigger, not by height. The kill itself is CCharacter::Die 0x19B3EE0 (100,000 damage, the float at 0x202ECBC; ApplyDamageInternal 0x2E4BE8). The engine's own world extents (+-5 km / +-3 km at 0x26C6588) only assert.

Height predicates. PredicateHeightAttackerIncluded (evaluator 0xEDD5F0) measures the height above ground with a ray cast from the character's position down to 100,000 cm (0x77A6D0) and tests it against a Combat/Predicates/Height range (On_Ground 0 - 50 cm, Jumping 40 - 5,000 cm). Every ground ranged attack carries On_Ground; 1,320 compiled attacks use it, 318 of them AI. An attack's AnimationData.EnableCollision / EnableGravity (combat +0x683 / +0x686) override the movement component's collision scale (0x41BEB4) and gravity (0x41C558) while it runs. The engine also has a native spectator movement state (NativeState.SpectatingState, SpectatorSpeedMultiplier1/2 10 and 0.1).

The player clock [[base+0x2702548]+8]+0x18 stops in the pause menu and while the game is unfocused; [base+0x2702590] keeps running.

Wraith World and the wraith companion

Wraith World is a weapon mode: Combat/PlayerWeaponModes/VisionMode -> Client/VisionMode::VM_Wraith; 0x6A6CE4 -> 0x6A7E90(vision = [player+0x2FA8], mode): +0x28 the mode record, +0x44 active, an amount that eases from +0x48 to the target +0x4C over the mode's 1 s ramp (ShaderVisionMode, read by 0x115EF98). The game changes nothing on the player's own pieces: Talion's solid shaders cut his body away with the same reveal map the wraith draws with (tRevealMapArray, k_fRevealValue). Orc and human shaders carry only k_fDissolve.

The wraith form is the player's companion model (Combat/CompanionModel): a copy of the player (CombatCompanionModelInstance vt_0x1DBD198; manager vt_0x1DCC8F8 at [[player+0x26A8]+0x80]: +0x38 body instance, +0x60 head instance, +0x68 companion record) built from a SimpleModel. Wraith moves add echoes that clone it (Combat/Echo::QuickThrow = three PC_Echo with CopyPlayerCompanion, material set Echo). Monolith's wraith pieces carry a default set of translucent wraith materials (wraith_game.fxo, fed the character's own textures) plus depth proxies (wraith_proxy.fxo) and an Echo set (wraith_riddick.fxo).

Material sets are compiled. 0x1B6190C builds a cache at start-up at [GM+0x6DD0]+0x18: one entry per Model record of 0x48-byte compiled sets. Editing a record later changes nothing there, and asking for a set index past an entry's count returns null.

Visuals, pieces and weapons

A visual (vt_0x1DA9610) has a spec at [visual+0xB8] (23 piece slots at +0x28) and a skeleton at [visual+0x90]. SetPieceSlot 0x4C62EC(spec, slot, piece, armour design, visual) swaps one slot live (the engine's live armour equip). A SimpleModel builder (0x4C5194) sets body, head, hair, accessories, flair and helmet from its entry; piece slots 8-12 come only from items. Pieces follow the host's pose through 0xF5A290 (pieces at skel+0x108 into the host's pose list); visibility 0x1BEE8C (skeleton, flag) is the engine's "hide the base model" (the material controller's HideBaseModel transform calls exactly that); 0x58BCF0 sets the material-set type.

Weapons are separate objects (vt_0x1DAA9D0: wielder +0x20, material controller +0x60, an inline mesh at +0xB0) drawn by per-slot holders [vc + 0x38 + slot * 0x28] (vt_0x1DB1F68: +0x140 the item, +0x148 / +0x150 the built models, +0x1F1 shown). A weapon skeleton has three bones (root, handle, tip). 0x3FD228 builds only an empty holder; an equipped, drawn weapon is rebuilt by the engine's refresh 0x45ABE4 per holder: 0x3FD21C (hide: destroys every model) then 0x3FD204 (show: builds from the item as it is now); the equip setup (vf35 0x3FCF70) does the same pair. The weapon's look chain: Inventory/EquippedWeaponData.Model -> _StructuresInventoryItemModel.Models -> _StructuresInventoryModel.ModelRecord -> a Model -> its default material set. Equipped weapon slots are vectors at vc+0x4D0 + i * 0x18 (0 sword, 1 dagger, 2 bow); an item's +0xA9 is "equipped", +0x40 its equipped-weapon data and +0x2C its holder index. The weapon TYPE comes from the item's Inventory/Items.WeaponType, copied into the built weapon object (+0x188, by 0x3FCF70): the active weapon is [char+0x2348] -> slot [vc+0x728] -> [vc + idx * 0x28 + 0x38] -> +0x188.

Runtime material slots. A piece's material object (piece+0x48, vt_0x1FFE3E8) has one table of 48 slots of 0x18 bytes from +0x1E8: slots 0-15 solid, 16-31 translucent (+0x368), 32-47 depth proxy (+0x4E8); a slot's first field is the .mat resource. The setter is the object's vtable slot 47, 0x17AF0C(object, kind, index, resource): kind 0 solid, 1 translucent, 2 depth proxy; it references the resource and posts to the render command ring, so it belongs on the main thread. SetMaterialSet 0x4DC938(skeleton, type) re-applies a set's solid entries.

Render IDs (SetRenderID 0x1BF144(visual, id), through the skeleton's vf4 0x1BF3AC onto body, head, pieces and attachments): the player 255, his wraith copy 254, a player-aligned mount 212, followers 210, enemies 220. In-world characters stay in material-set type Wraith permanently (the type's override is the pale vision glow); no shipped Model carries a Wraith-typed set (set types in use: default 2,644, GhostWeapon 133, Echo 78, HierarchyUnknown 65, PlayerCompanion 17, Death 11).

Mounts. The ridden mount is [player+0x2578], its rider [mount+0x25A0], its visual [mount+0x2340]. A mount has no material controller (its combat object's +0x390 is 0).

Talion's material controller

ctrl = [[player+0x26A8]+0x390] (no vtable). It animates the shader parameters of Talion and of his wraith double; no other character has one (0 of 43 spawned characters).

Offset Meaning
+0x00 / +0x08 its link in the global list of animating controllers (mgr+0x1370, walked by 0x58B44C from the world tick 0x1F6EC4)
+0x30 owner
+0x60 the Combat/FX/MaterialController/Setup record (Setup::Player)
+0x80 an attack-linked state
+0x88 / +0x90 handle references to Talion's parameter block (self) and the double's (child) (vt_0x1DC47B8)
+0x98 / +0xB0 the parameter entries (0x40 each)
+0x100 the active state nodes (node: +0x00 state record, +0x10 expiry)

A parameter entry: +0x00 the parameter name's hash, +0x04 the priority of its driving state, +0x08 an easing object (only while easing), +0x10 / +0x14 start and end time, +0x18 the transform driving it, +0x20 default, +0x28 current, +0x30 from, +0x38 to. Value objects (float vt_0x1DC8930, int vt_0x1F9FF30, ARGB vt_0x1F9FE70; value at +0x08) push through their slot 2 to the handle's setter (SetParamFloat 0x3094FC, int 0x57AC84, SetParamVector 0x47E4540), each posting one render command.

  • SetSetup 0x739BC0(ctrl, setup) builds the entries (0x73A5E8: the RestoreDefaultTransform value if a transform names the parameter, else its initial value) and returns immediately when the setup is already current, so the setup record is read only when it changes.
  • The update 0x58B488 -> 0x58B850 eases entries (current = lerp(from, to)) and pushes; an idle entry pushes nothing.
  • AddState 0x58E320(ctrl, state, ...) is refused when the state's tag is in the setup's StateTagRestrictions (0x58BAFC); an entry follows a state only when its priority is at least the current driver's. RemoveState 0x58B370 removes every node of a record; each parameter it drove eases to the next remaining state's value, or to its default. A state that drives a parameter the setup does not list creates an entry whose default is that state's value. The script bindings are CPlayerObj::AddMaterialState 0x19BB020 / RemMaterialState 0x19BEF8C.
  • After every equip the engine re-attaches the blocks (0x7A7738: the self block to the player and the held weapon, the child block to the double), because a piece added later is set up by 0x4C6EFC without them.

The 168 material states are parameter states; none hides a model or swaps cloth. WraithRadiance, Vanish, WraithPing, Domination, Tower and GameChanger set Talion's k_fRevealValue 0 and the double's k_fRevealArm 1 and k_fOpacity 1 (the body cut away, the double shown); TalionDeathSwitch shows both; HandOfGod and Stealth draw a fainter double; _Curse sets k_fCurse 1; Player_Eltariel, TalionWraith and DarkTalion are colour sets.

The wraith shader (wraith_game.fxo, skeletal pixel shader): the material constant buffer cb3 follows the .mat parameter order (cb3[9] fixed-reveal width and active, reveal width and arm; cb3[10] fixed-reveal arm, reveal map index, dissolve, fresnel minimum; cb3[11] fresnel maximum, alpha floor, opacity, opacity minimum; cb3[12].x bloom scale). Reveal = saturate((sample + (W + 1) x Arm - 1) / W) x (1 - Dissolve) with W the reveal width; alpha is roughly fresnel x reveal x k_vObjectColor.w x opacity x diffuse alpha. k_vObjectColor is a global shader-constant object (0x2A39FA0, value at +0x40) filled per draw (0x254B80) from a packed colour at draw item +0x4C.
