Schema Builders — declared schema from CODE (CRACKED 2026-08-03)

call("schema_from_code", field="BaseSpeedMultiplier") / call("schema_builder_decode", rva=...), OFFLINE. Module aire/analysis/schema_builders.py.

Every field has its own ~90-byte registration stub (1 caller, 1 callee) whose strings are that field's name AND its own annotations; a per-category builder calls every stub in declaration order. Binding comes from the CALL, so it attributes what the deduplicated string pool cannot:

sub_843EDC                        <- Client/PlayerMovement builder, 36 stubs
  0xC75150   "GROUP_BEGIN=ThermalVent"
  0x1631698  "AimingRadiusScale", "min=1.0"
  0x16316F8  "public Tags", "AimingTeleportExclusiveTags"
  0x163580C  "BaseSpeedMultiplier", "min=0.0"

Validated 34/34 fields, 0 code-only, 0 live-only = 100.0% against the live descriptor run. Yields what live descriptors do NOT carry: declared TYPES, min/max constraints, and GROUP_BEGIN/GROUP_END (the markers this file says are absent from runtime descriptors — they are, they live in the builder). Coverage: 99% of field names have a stub, 91% reach a builder (random 300-name sample, 215 distinct builders).

FULL SWEEP — call("schema_builder_sweep", out="tools/re/data/declared_schemas.json"), ~90s: 14,387 stubs -> 2,382 builders, 0 decode failures; 17,094 fields, 7,154 with a declared TYPE, 1,443 with min/max. Category identity is a TWO-SIDED (F1) field-set match with a floor: 1,003 identified + 39 partial_builder, 1,020 distinct categories. A one-sided score let a 63-field builder claim a 3-field category off one shared name (Predicate) — 58 builders all claimed _StructuresMoraleInfluence. The 1,340 "unresolved" are NOT missing schemas: median field count 1, and the 89 substantial ones are mostly other reflection tables (script API __index/SetVisible, FX KeyName/BindToObject). type=EFalloff is a second annotation form alongside public <Type> (+638 types).

Derived artifacts (aire/analysis/declared_types.py):

call("declared_fk_export",     out="tools/re/data/declared_fk_types.json")
call("declared_ranges_export", out="tools/re/data/declared_ranges.json")
call("declared_unresolved")

declared_fk_types.json — 7,154 declared types, 5,146 resolved to a real category, of which 1,182 are dormant_declared: an FK target the live sweep CANNOT produce because the field is NULL in every live record. declared_ranges.json — 368 categories, 1,088 declared min, only 3 max (bounds are floor-heavy; atlas envelopes remain the source for upper bounds).

Declared types validated against the live FK map: 3,722/5,015 = 74.2% (baseline 3.3%). The declared type is a TYPE name, NOT the category path — a naive compare scores only 33.7%. Observed relations: Quest.QuestList->Quest/QuestLists (pluralised), Faction.FortAssaultGroup ->Faction/FortAssault/Group (segments CONCATENATED), Interface.KeyMap->Interface/GFX/KeyMaps (middle segment dropped). GADB Field Bindings — the schema OBJECTS, and who reads each field (CRACKED 2026-10-05)

aire/analysis/field_bindings.py; call("field_bindings_build") / call("field_binding", ...). OFFLINE (~75 s), LIVE-VERIFIED. Schema Builders (above) say who DECLARES a field; this says who READS it.

Every reflected type has a static SCHEMA OBJECT in the zero-at-rest part of .idata (file-backed only to 0x26F8E00): one 0x48-byte slot per field, zeroed by a static initializer that then tail-calls the builder:

sub_A7EB0:  lea rcx,[0x2955C80] ; mov r8d,0x1B0 ; call memset ; jmp builds_schema:AI/Templates
builder:    lea rcx,[0x2955C80] ; lea rdx,"GlobalVarUnlock" ; call PropRegister 0xC6DA00   (inline)
            lea rcx,[0x2955CC8] ; call registers_field:AI/Templates.CharacterModel        (stub)
stub:       mov rbx,rcx ; mov r8d,0xA (type) ; lea rdx,"CharacterModel" ;
            mov [rsp+0x30],2 (flags) ; call 0xC6DA00

0xC6DA00(slot, name, type_code, &default, ...) is the SAME PropRegister the ClientFX node factory uses (same 0x48 stride) - GADB categories, ClientFX nodes and BlendDB (.bvr) types are one reflection system. Slot k = descriptor absolute index k, except that a GROUP_BEGIN/END marker is a slot too (arg 7 0x80000080 / 0x40000080, annotation GROUP_BEGIN=<group>) and owns no index. The memset size is the object's exact extent (AI/Templates 0x1B0 = 6 slots, Character/Models 0x1D40 = 104).

A compiled getter names its field only through the object. GetCharacterModel 0x16680C calls three per-field leaf helpers, each loading a CONSTANT POINTER to the object ([0x266CB70] = 0x142955C80 at rest) and touching slot 1:

slot+0x20  lookup key    (0x1822494: mov rax,[G] ; add rax,0x68 ; ret  -> slow path 0x115AE24)
slot+0x30  state         (0x166858:  cmp dword [rax+0x78],2 ; setge al  -> descriptor cached)
slot+0x40  u8 index      (0x166868:  mov al,[rax+0x88]  -> fast path 0x30E7B4/0x47E6F50:
                          value = [rec+0x10] + ([desc+0xE] + i)*8, desc = [rec+8] + index*16)

So (object, offset) IS a field identity - no displacement guessing.

The TYPE TABLE - what binds a category to its object (CRACKED 2026-10-05)

aire/analysis/type_table.py; call("type_info", ...) / call("type_table_capture"). The engine keeps a static reflection TYPE TABLE in the file-backed part of .idata - the same 0x40-byte entry shape as the ClientFX "Table A" (they are one table system):

+0x00 schema object   +0x08 slot count (== the memset extent, 2,699 / 2,699)
+0x10 short name      +0x18 description / "Struct" / empty sentinel 0x1DB10E0
+0x20 TYPE NAME       +0x28 PARENT entry (single inheritance: 517 of 2,686 derive)
+0x30 0               +0x38 flags (0 / 2 struct / 8 / 10)

0x266CB70  0x2955C80  6     Template  -                              AI.Template
0x264ABA0  0x286D8B0  0x68  Models    "Character Model definitions." Character.Models
0x2650EE0  0x28CCCC0  0x13  Node      "Data for a Melee node"        Combat.Node

The getters' "constant pointer" ([0x266CB70]) is entry +0x00 of this table. A LIVE category header holds its type entry at +0x20 (AI/Templates -> 0x266CB70), and the on-disk GADB names each category's type (gadb_category_index type). Scan: 3,099 entries; all 2,686 entries the live links prove real are found; every parent pointer lands on another entry. The offline type-name join agrees with the live link for 2,706 categories and contradicts it 0 times; the 7 it cannot split are names registered twice (CurveInt/CurveFloat/CurveVector/CurveColor/ CurveFile exist as both a ClientFX and a GADB struct; WorldUI.StorePredicate twice). 29 categories have a NULL type link live. Names may contain a SPACE (Profile.Bindings PC).

Schema slots, live (type_table_capture, read-only, 3.7 s). PropRegister 0xC6DA00 fills each 0x48-byte slot at start-up: +0x00 name ptr, +0x08 annotation, +0x10 default (16 B), +0x20 P919(name), +0x24 type code, +0x28 arg 6, +0x2C flags (GROUP 0x80000080 / 0x40000080), +0x30 state (0, cached >= 2 later), +0x38 accessor (called once), +0x40 its return = the descriptor index. One read of the zero-at-rest data gives 26,935 slots of 2,951 types, all 26,935 named and every name equal to the hash the engine stored beside it, 2,463 group markers. The image never moves, so category_types.json + schema_slots.json (aire/data/engine/field_bindings/, exe-fingerprint guarded) serve every later session offline. Measured across two launches (PID 37456 -> 32240, both in Minas Ithil): category links 2,742 / 2,742 identical, all 26,935 slots identical (name, hash, type, flags, accessor), and of the 22,630 slots cached in both, the engine's cached descriptor index differs 0 times - the binding cache is a deterministic start-up fact, so the field-binding oracle holds offline.

The engine's own field-read path (DECODED 2026-10-27, MEASURED)

Every RecordLink field accessor (5,215 of them) is one template that calls BOTH halves of the read, and the two caller sets are identical (5,215 / 5,215 / intersection 5,215):

accessor(record):
  slot = the field's static PropRegister slot (0x48 B, filled at start-up)
  if [slot+0x30] >= 2:  GetLinkCellFast 0x30E7B4(record, byte [slot+0x40], elem, &default)
  else:                 GetLinkCellSlow 0x115AE24 -> GetLinkCellByName 0x68BB08(record, &hash, ., elem, &default)
  • GetLinkCellFast 0x30E7B4 (leaf + tail in .bss a 0x47E6F50): descriptor [rec+8] + idx*16, elem < u16 [desc+0x0C] else the default, cell = [[rec+0x10] + (u16 [desc+0x0E] + elem)*8]. No type check: the cached index already proved the field.
  • GetLinkCellByName 0x68BB08: FindDescriptor, then type & 0x3F == 10 (RecordLink) and elem < count, same cell read. If record byte +0x01 has bit 0x10, the read goes to ReadLinkReflected 0x16CE2E8 instead (below).
  • FindDescriptor 0x25180C(record, &hash) (693 callers): binary search over the record's 16-byte descriptor run. Record byte +0x01 bit 0x01 -> the run is sorted by its own +0x00 hash and is searched directly; bit clear -> FindDescriptorPermuted 0x251BD0, which searches the +0x04 column (the run's hashes, sorted) and returns run + byte [entry+9]*16. This is the sort index schema_guard documents (aire/gamedb/schema_guard.py): the run stays in field order and carries its own sorted permutation.
  • ReadLinkReflected 0x16CE2E8 -> ReadReflectedField 0x5DA158(type, &hash, record, elem, &out): the category's TYPE entry [[rec+0x18]+0x20] (see the type table above), FindSlotByHash 0x251BA8 (linear over the type's 0x48-byte slots, key slot+0x20), SlotOffset 0x251C24 (walks the slots in order, accumulating each one's size and alignment through 0x251CAC, not decoded) and reads the record's instance as a NATIVE STRUCT: inst + offset; slot type 8 / 9 = 16-byte elements; slot +0x28 (arg 6) == -1 = a {ptr, u32 count} vector with a bounds assert (null write at 0).
  • Live census (2026-10-27, in world, read-only): all 278,865 secondary records of 2,742 categories have byte +0x01 == 0x0A (bits 0x01 and 0x10 clear). A GameDB record therefore always takes the permuted search and the instance cell; a live FK write is never bypassed by the reflected path. schema_guard.capture skips any record whose tag is not 0x0A; that loses nothing for the main GameDB (0 such records).
  • MEASURED 2026-10-27 (was a LEAD): BlendDB records ARE the flag-0x10 population. All 318,372 live BlendDB records (3,316 categories of the loaded .bvr graphs, found through their type entries) carry +0x01 = 0x1A. Their instance is a NATIVE STRUCT laid out by SlotOffset: each slot in order takes size rounded to 8 (0x251CAC: 0 for flags & 0x280 - group markers and editor-only fields; 16 for arrays (arg6 != 1) and Vector4; 12 Vector3; 5 Bool; 8 other scalars). Read at those offsets, BlendState Priority / DefaultBlendTime / StartPct / Looping / Mirrored / Gravity equal the disk decode for 10,697 / 10,697 records each (control +8: 0 / 0 / 2 on the discriminating fields). aire/formats/blenddb_layout.py, actions behavior_field_offsets, behavior_live_node. The 0x01 (sorted run) population is not found.

GADB Field Consumption — does a live edit take effect, and when (BUILT 2026-10-05)

aire/analysis/field_flow.py (+ the generic follower aire/analysis/value_flow.py); call("field_flow_build") (~70 s offline) / call("field_flow", category=, field=) / call("field_flow", rva=) / call("field_flow", verdict="copied", prefix="Combat/"). Folded into explain (field_consumption) and the engine graph (stage field_flow).

A GADB write always lands; whether it CHANGES anything depends on what the reading code does with the value. Field bindings name the readers; this follows the value out of each read:

verdict fields meaning
live 8,685 used where it is read (compare / compute / deref / passed on): an edit applies the next time that code runs
copied 2,275 stored into an IDENTIFIED object (typed, handed in as an argument, or a global): an edit applies when the COPIER runs again
both 695 some consumers use it, others copy it
stored 144 stored only where the destination is unresolved (a container slot a call just returned)
returned_only / unknown 112 / 878

(12,789 fields; 5,752 strong copies, 653 fields with a TYPED destination.) Every copy says what it CARRIES: value; pointer (a float-pool pair / vec POINTER: editing the values behind it stays live, repointing the cell needs the copier); link (a RecordLink's record pointer: same, for the linked record); derived (computed from it - Bool.Value read through a link, a unit scale); flag (a constant stored on a branch taken from the value - compiled present = 1 / max > 0 bytes). Every copier carries triggers = its NAMED ancestors (console commands, script bindings, known functions, named vtable methods, message strings) = what re-runs it.

Oracles, both recorded independently by live work: the PlayerCompanion group compiler 0x1881264 - 11/11 documented fields copied at the documented offsets; the targeting-cache compiler 0x1C0B634 (arg0 = entry + 8) - 10/10 documented entry offsets including both control-dependent flags:

e+0x0C/+0x14  DistanceRange / DistanceRangeNoInput max (loaded THROUGH the pool pointer)
e+0x20/+0x24  ScreenWidth (held in xmm1 across the next accessor) / ScreenHeight
e+0x168       MaxAngle            e+0x195  RequireLOS
e+0x190       MaxDistance_PlayerAlly * 100.0 (`mulss [0x202E8C4]`: the field is in METRES)
e+0x1B5       flag, set when that product > 0.1   (the "compiler sets the byte iff max > 0")
e+0x1B0/0x1B1 RequireStraightPath: present = 1 when the link is set; value = Bool.Value(link)

The whole compiled layout: call("field_flow", rva=0x1C0B634) (69 fields).

Measured mechanisms the follower needed (value_flow.py, each found on a real function): xmm clobber sets; the prologue stack model (mov rax,rsp ... lea rbp,[rax-0x57] makes [rbp-0x30], [rax-0x38] and [rsp+0x20] one key); out-parameters and ARRAY ITERATORS (lea rcx,[rbp-0x30]; call init(iter, rec); call at_end(&iter); call current(&iter) - array fields never return in rax); a field accessor handed an already-tracked local is REFILLING it with another field (0x499724 reuses one out-param for every accessor - without this, one field "copied" its neighbour's value); intra-function jumps to a merge point; chained getter reads; SETcc/CMOVcc on value-derived flags. Generic readers are found by BEHAVIOUR: a callee whose RESULT a one-field wrapper returns, or that it tail-jumps to (jmp sub_1CB3B0 in 1,081 wrappers). Counting calls admitted the engine assert 0x819104 (every wrapper calls it on failure) as a "reader".

"Many fields copied" does NOT mean "runs at load" — a compile_time verdict was built and WITHDRAWN the same day. _StructuresCombatAttackData.AOE / AOEOnStart came out compile-time, but the in-game blast-on-arrival came from LIVE writes to exactly those cells: the copier 0x2DED44 sits under CombatProp::PlayAttack / CPlayerObj::StartAttackType, i.e. it runs at every attack start. When a copy is refreshed is answered by the copier's TRIGGERS: - targeting cache 0x1C0B634 <- 0x1B69838 <- "Failed to initialize subsystems" / RestartRender (load time); - PlayerCompanion groups 0x1881264 <- Player.SetCharacterModelOverride / ClearCharacterModelOverride / SetModelOverride / SetPlayAsFactionMemberNPC / Skin_User_Selection - LEAD (call graph, not run): the user-tested "live edit changed nothing" should take effect after a skin / model change; - Client/PlayerMovement.BaseSpeedMultiplier is copied to player +0x550 by 0x187F94C, under the same model-override family - LEAD that a skin change re-applies movement fields without a fast travel (the type table calls PlayerMovement "console variables").

Coverage limit, stated: a field with no field-binding reader is not_read here (20 of 36 Client/PlayerMovement fields, e.g. StandCapsuleHeight - its slot has no helper anywhere, so it is read by a path the schema objects do not show). Freshness follows field_bindings + type_flow outputs. Tests: tests/test_field_flow.py (both oracles, xmm case, behaviour readers, the withdrawn compile-time claim).

GADB String Block — offset base (CORRECTED 2026-08-02, live-verified 100.00%)

String offsets are measured from the ROOT TYPE NAME, not from the parser's sb_start. The root type ("GameDatabase\0" — 12 chars + null = 13 bytes) IS string offset 0 of the block.

"TWO DIFFERENT ORIGINS, BOTH REAL" IS WITHDRAWN — CORRECTED 2026-08-16. THERE IS ONE ORIGIN. This section used to add that h[0]/string_block_size and therefore desc_start are measured from just AFTER the root type. They are not: h[0] INCLUDES the root type name, so

desc_start = root_start + h[0]                      (NOT root_end + 1 + h[0])
val_start  = desc_start + descriptor_count * 15     exact — no fudge, no search

Verified exactly, three containers with three different root lengths:

container root type root_len root_start + h0 + n*15 measured val_start
world layer OBJR block ObjectPropertyDB 17 46 + 2236 + 3825 6107
.bvr behaviour graph BlendDB 8 115 + 64684 + 31905 96704
main GADB (hotchunk[0]) GameDatabase 13 71 + 10412928 + 5429085 15842084

The old desc_start was high by exactly root_len, which is what the value-section "13 bytes fewer" search was absorbing — and it is also why the DISK DESCRIPTOR FIELD ORDER was recorded 13 bytes off (see the Anvil decoder section above). The parser's fixed - 16 search window worked only while root_len <= 16, so every container with a 16+ character root type refused to parse at all — ObjectPropertyDB (17) raised "Cannot locate value section preamble in GADB", which made every world placement layer look like an unknown format. Fixed in official_gadb_modifier.__init__: derive nominal_end - root_len, check the preamble is there, else fall back to the scan widened by root_len. Control after the change: OpsCaragorCage fc 11 and the same ScenarioType, 22 SpawnAmbient categories, 250 distinct AITypes — unchanged.

OfficialGADBModifier._read_str used to compensate with a BACKWARD WALK to the previous null. The block uses shared-SUFFIX storage, so any name that is a suffix of a longer string came back as the enclosing string — "Unpause" read as "GameUnpause", "DLC4_GliderDissolvePitch" as "\CDLC4_GliderDissolvePitch", some record names as a neighbouring category name. _find_full_string (category paths) was worse: its >= string_block_size bound also rejected the tail of the block, so ~95 categories parsed with an EMPTY path.

Fix is surgical — sb_start/desc_start/val_start/rebuild math must NOT move, only the string base: str_base = root_start, str_span = string_block_size + 13, forward read, no walk.

Measured against live memory, full sweep of every record in every category: 263,815 / 263,818 exact (100.00%) vs 67.4% for the backward walk (3 residuals are non-ASCII).

The parser's own -16 fudge for a value section "13 bytes fewer observed in practice" was the SAME 13. A magic constant appearing in two unrelated fudges is a base error, not a quirk — and a compensating heuristic ("walk backward to find the true start") is a bug report, not a solution. This warning was right and was still under-applied: the same 13 turned out to be load-bearing in a THIRD place (the disk descriptor field order) and a FOURTH (desc_start itself). When a constant equals the length of something in the file, it is that thing — chase every use of it.

Anything derived from Anvil record/category names before 2026-08-02 may be wrong for suffix names. Rescan the archive index rather than trusting the cache (done 2026-08-02: 374,288 records re-indexed; list_records now returns Pause/Unpause, was GamePause/GameUnpause).
