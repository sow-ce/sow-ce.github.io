Live bundles — load any shipped bundle into the running world (PROVEN IN-GAME 2026-09-25)

Any .bndl the archives ship can be made resident live, from any region, through the engine's own bundle registry — no hook, no file change, nothing persists. A/B proof, user-confirmed: the catapult impact's AOEFX string was pointed at fx\demo\grondcageexplosion.fxp, an effect that ships ONLY in the Mount Doom fort layer. Volley A (bundle absent, live_resource = not resident): firebombs landed with NO explosion. Live-load dlc3_fortmtnpass.bndl (46 MB, live_resource = resident). Volley B: "way more catapult bomb".

The registry (owner built by 0x119E5D4, which publishes owner+0x30 in [base+0x2A86750] and owner+0x800 = the resource system in [base+0x2A86758]):

owner vt 0x22C0FF8 (+8: 0x22C0FC0)    slot 24 0x3DC538(owner, Bundle** out, path) forces .bndl
owner+0x718  registry: +0x28/+0x30 rows {u64 hash, CResourceBundle*, u64}, 0x18 each
get-or-create 0x1B5DC0(registry, path, &handle)
CResourceBundle vt 0x1E6E678 (0x178 B): slot0 AddRef 0x3DEDA0, slot1 Release 0x3DEA38,
  slot2 Prefetch 0x3DECC8, slot3 Discard 0x3DEAEC
  +0x08 char* path  +0x14 refs  +0x18 LOADED CONTENT (vector of resource handles)
  +0x20 manifest resource (+8 data: null = the .bndl does not exist)
  +0x28 u16 prefetch count  +0x2A u8 GENERATION (++ per load and per discard, not a state)
  +0x70 paired .embb path

Laws, each measured: - The registry row holds NO reference. Release at zero unregisters and destroys the bundle (0x1B5C9C), detouring to 0x10DD00A if the prefetch count is still nonzero; Discard asserts it is never the final release. Contract = keep a HANDLE and a PREFETCH; unload = Discard THEN Release. live_bundle_unload returns exactly the pairs its per-process journal took. - Ask for the SHIP path. AIRE's index path drops folder segments the archive folder table stores (cloaks\player_rhovaniont3_cloak.bndl is cloaks\rhovanion_cloak\..., sectionsandlayers\dlc3_fortmtnpass.bndl is sectionsandlayers\dlc3\...). The short form registers an entry whose manifest never arrives (benign — the engine ships 10 such rows). live_bundle_load resolves through model_asset_path first. - Loading a region's layer does NOT place it. 32 world contexts before and after the fort load, objects 73,893 -> 73,870 (streaming churn). Its 121 resources load in the same state as engine-loaded bundles (data present, flag 1) while the world stays unchanged. - Every character bundle is already resident in a loaded region (Balrog, Witch-king, Graug-a-pult: 544 registered, 534 loaded) — region CONTENT is what is missing. - An unreferenced resource is CACHED, not freed (0x1BEAAC: refcount 0 -> unlinked from an unused list at +0x10 and reused). "Discarded" is not "gone"; test residency BY NAME. A/B tests must run the absent volley FIRST — once an effect played with the bundle loaded, unloading does not reliably remove it.

Resource residency by name (live_resource): StringHash 0x423E70 = P=919 over the LUT at 0x1DB50D0, seeded by r8 (pass 0; the loop never clears it); table resSys + (h & 0x7FF)*0x18 (0x800 buckets, head +8); node = resource+0x10 (+8 next, +0x10 hash); resource +0x08 data, +0x28 name, +0x30 refs, +0x52 type (27 bundle, 48 .fxp, 20 .mat). Control: globalrenderingconfig.bndl resident, an unloaded bundle's manifest reads absent.

fx_dependencies reports world-layer-carried materials as UNRESOLVED (its BundleIndex cache is partial). Before calling an asset missing, read the carrier's own path table (embb_probe) and the live table (live_resource).

call("live_bundles", filter="dlc3")                        # the live registry (no focus needed)
call("live_bundle_need", asset="fx\\demo\\grondcageexplosion.fxp")   # which bundles carry it
call("live_resource", paths=["fx\\demo\\grondcageexplosion.fxp"])    # resident right now?
call("live_bundle_load", path="worlds\\retail\\mtnpass\\sectionsandlayers\\dlc3_fortmtnpass.bndl")
call("live_bundle_unload", all=True)

Module: aire/pipeline/live_bundles.py (journal aire/data/live_objects/bundle_journal_session_only.json). Main-thread calls — the game must be focused and the poller mounted in this process.

An armour piece needs TWO bundles (IN-GAME CONFIRMED 2026-10-08)

Geometry = <piece>_g.bndl (piece ArmorDataDynamicBundle: .mesh/.skel/.anix only). Material + textures = a set-wide <set>_<slot>_m.bndl (flair\rogue\rogue_chest_m.bndl: 2 LTMI + 4 TEXR, shared by the Slim/Buff/Stk/Olog pieces), named by the DESIGN: Inventory/ArmorData slot 0 DynamicBundle (hash 0xDF9F0919, the dictionary's "BaseWeight" collision) on the AD whose ModelPicker lists the piece. The engine loads both through a gear load request (vt 0x1DB4F78, ctor 0x400AB8: AD.DynamicBundle + EWD.DynamicBundle + piece.ArmorDataDynamicBundle, registered with [GM+0x6C88]), created ONLY for an equipped ITEM (orc give path 0x355474 -> 0x61B868 -> 0x4B4C7C, item equip 0x40136C -> 0x401680, item re-skin 0x645890). A piece written straight into an appearance gets no request: mesh in memory, its .mat a registered resource with NO DATA -> bare torso or warped skin. MEASURED after a MAX roll (Lithlad): 23 of 219 worn pieces / 10 of 22 captains, all randomizer picks; loading their 19 _m bundles live filled the same stubs (refs 3 -> 5, data present), census 0 of 219 missing, and the captains dressed on screen. The save loader 0x1C112F8 restores non-item pieces (smc_nonequipment_record_list -> 0x1162D40) with no request, so a saved roll needs its bundles requested again after every restart. Framework: sdk/sow_gear_residency.hpp MaterialIndex + ArmyRNG::PumpRegionDressSweep (built, NOT run).

A bundle the engine holds for SOMEONE ELSE's item is borrowed (MEASURED 2026-10-17, live census). After a Safe roll in Minas Ithil every armour slot of 25 captains held a piece and the trace said "0 waiting, 0 not loadable", yet 4 of 148 worn pieces drew nothing: Nakra's legs / Luga's arms were Orc_Buff_Industrial_*, resident only because two Machine-tribe Buff captains wore the Industrial tribe items in the PREVIOUS roll. This roll changed their tribe; the rebuild dropped their gear requests, the bundles were released and their registry rows destroyed (no orc_buff_industrial_*_g row at all; the piece's .skel a resource with refs 1 and no data, its .mesh absent; control Glutton pants both resident). A 5th piece had its mesh but a .mat with no data (the design's _m released the same way). GearResidency counted an engine-held path as Resident and took no reference. Fix (built, cl /Zs clean, NOT run): Service::Hold takes our own handle + prefetch on every engine-held path before a piece goes on (getter on a registered bundle = same object; 0 MB; refused below the gear cache's VRAM reserve), and the randomizer's settle-time DRESS AUDIT checks every worn piece in the resource table (.mesh by the .skel's stem + every .mat of set 0 with data; a Python twin flagged exactly the broken 4 of 148, 0 unknown) and re-seats a missing one (empty piece, then the piece) once it loads.

Foreign-game models in game — the Halo CE Pelican (PROVEN IN-GAME 2026-09-25)

User screenshot: orcs in Minas Ithil swinging the Halo: Combat Evolved Pelican as a weapon. No archive edit, no restart, no hook. The chain, every link measured:

  1. Donor out of the other game — aire/model/halo_ce.py reads MCC halo1\maps\*.map (Halo CE cache, version 13, stored UNCOMPRESSED): tag index -> mod2 gbxmodel -> parts (68-byte vertices, u16 strips) at any LOD -> OBJ. Pelican = vehicles\pelican\pelican in b30.map, 10 parts, 5,668 verts, 32.3 m at 3.048 m per Halo unit. Any CE vehicle/weapon/character reads the same way.
  2. Into a SoW mesh — rigid import into a copy of a WEAPON mesh (slave_broom.mesh), bound to the palette index the carrier's own geometry uses (both broom groups: palette [1] = broom_handle), shipped with a byte copy of the carrier's skeleton under new paths.
  3. Live — a custom bundle (bundles\sowce\sowce_pelicanwep.bndl) served by Live VFS and loaded with live_bundle_load; then Model.ModelFile (a live char*) of 68 orc melee weapon records repointed to characters\sowce\pelican\pelican_wep.skel (journaled, pelican_arm.py --revert). Orcs BUILT after the swap carry the Pelican; existing ones keep what they built. A loading screen re-deserialises the GADB and undoes the repoint (the bundle stays resident) — re-arm after travel.

What did NOT render, and why (do not re-attempt): - ClientFX Model nodes on an AOE impact draw nothing — not our Pelican, not a byte copy of the shockwave ring, not even the SHIPPED globally-resident ring with the rest of the Grond effect hidden (control). Effects are the wrong carrier for models in this context. - Placed props are baked layer geometry. A world context's per-name table (ctx+0x98: sorted P919 name hashes -> 744 shared records of cull radius/bounds/material instance; T+0x48 pieces are .mat instances, not meshes) — a new object cannot be pointed at a .mesh through it. - Weapons (and characters) render a model BY PATH — Model.ModelFile names the .skel, the .mesh pairs by stem. That is the carrier that works.

Traps measured on the way: - graft leaves a resized arena's LOD ladder stale — [800 x15, 4469] after importing into an 800-triangle arena (only the last slot updated). Fix structurally: parse_container -> ladder u16[16] at blob_off + arena_table + i*48 + 0x10 = the arena's triangle count; bounding sphere at blob_off + 0x2C (cull, cx, cy, cz, radius). Their FILE offsets move with the arena count — hardcoding the 1-arena offsets (+0x60/+0xA0) corrupted a 2-arena mesh. - decode_skeleton gave every bone its SUCCESSOR's name (FIXED 2026-09-25, all v17 rigs). A record is [u32 name_off][u8 flag][f32 pos[3]][f32 quat[4]][u32 children]; the reader took name_off from quat+20, which is the NEXT record's. Positions and the tree were right, only the labels slid by one (record 0 is Null, last name came out ull). Verified on the drake (Pelvis has spine+2 legs+tail, Head has 10 face children, Saddle sits on the neck) and the player rig (Null, pNull, Pelvis, Torso_Base ... L_Hand, 80/80 L/R bones on one side). Consequence: any earlier by-name lookup (incl. geometry calibrate labels) pointed at the neighbouring record — e.g. R_Hand resolved to R_Arml. The broom (3 bones) still decodes wrong — a separate small-SKEL defect, unsolved. - A vertex palette byte indexes the SKEL NAME-TABLE order, Null = 0 — not the bind array. The name table is written level by level (Null, Pelvis, Spine1, L_Legu, R_Legu, Tail, Spine2 ...). Skinning oracle on the drake: co-weighted bones within 2 tree steps 74% (name-table) vs 33% (record order) vs 2% (random); median vertex-to-own-bone 26.5 vs 106.6 vs 445.7. Holds on 6 player body meshes too (0.47-0.68 vs 0.04-0.13). SowSkeleton.runtime_names / runtime_of(); retarget._map_bones maps by name into this space. - tools/re shadows the stdlib re once tools/ is on sys.path (the scripts' fxp helpers add it) — import re/json before it, or the next import json dies in a circular import. A scratch script named inspect.py shadows the stdlib inspect the same way.

A creature wearing a foreign body — the Pelican drake, via Blender (PROVEN IN-GAME 2026-09-25)

User screenshots in Lithlad: the summoned drake mount renders as the Halo CE Pelican, flies with the drake's own AI and animation, is ridden ("Hold [L SHIFT] Grab Enemy"), and its fire breath comes out of the Pelican's nose. No archive edit, no hook.

  • The drake = 2 model pieces + 1 animation rig, all in bundles\modelcharacters\fellbeast\ fellbeast.embb (ui_assets.arch06, 37.9 MB, 213 sections): Model/Smp_Fellbeast_Body -> body\fellbeast_body.skel/.mesh (10 groups / 8 arenas: LOD0 arena 6, LOD1 arena 7, 6 gore-cap LOD arenas), Model/Smp_Fellbeast_Head -> head\fellbeast_head.skel/.mesh (head AND wing membranes), Model/Cha_FellBeast -> fellbeast_base.skel (146 bones; body/head rigs are the same 134 bones with identical bind poses). MaterialSets = 2 primaries x 4 .mat cells: set 0 live (body, bodylods, 2 gore caps), set 1 the DEATH swap (fellbeast_death.mat ...) — repoint both.
  • Blender route (headless, blender.exe -b --factory-startup --python): AIRE exports the rig (corrected names, bind heads) + reference meshes in Blender axes — SoW = (bx, bz, by) x 100, a mirror, so winding flips on the way in; Blender builds the armature, fits the donor, binds it by VERTEX GROUP named after the bone, saves a .blend for review and exports a skinned .glb. AIRE load_donor(glb) -> retarget.plan(space="gltf", scale=100, align_feet=False) (align_feet would re-centre it) -> 134/134 bones mapped into runtime space, placement round-trips EXACTLY.
  • Emptying drake groups: graft a one-triangle degenerate group into every group you do not want drawn (keep_carrier=False); flat LOD ladder = arena triangle count (the shipped drake mesh is flat); recompute the bounding sphere, never radius 0.
  • Vertex colour is a MASK on this rig (R binary, G/B 255, A small; lowest LODs all R=255): the importer's median fill gave R=0 = the special value; write (255,255,255,0).
  • OBJ -> Blender needs OBJ V convention (export_obj(flip_v=True)); Blender's glTF export flips V back to the top-down space the engine samples. The DDS-convention OBJ the direct route wants came out V-inverted through Blender (hull sampled the bay half of the atlas).
  • Where it can be armed: the main-thread poller lives only in Minas Ithil script layers and drakes cannot be summoned there. Load the bundles in Minas Ithil (+ pin fellbeast.bndl), fast travel, then write the Model records AFTER the loading screen (writes need no main thread; loaded bundles survived the travel). scratchpad/drake/arm_drake.py --load | --write | --revert.
  • Lithlad (desert) layer scripts are PRECOMPILED: SCRI flag 0 = HavokScript bytecode (\x1bLuaQ + TNIL..TSTRUCT type table); flag 1 = Lua source. All 8 standalone Lithlad parts are flag 0, every base region ships source (99/115/97/105/86 source hosts), so the text-injection poller cannot host there. Candidate route: a flag-1 part that loadstrings the original bytecode, then wraps its StartupCommands — needs a binary-loadstring test in a private VM first.

Custom bundles — content that exists in NO archive, loaded live (MEASURED 2026-09-25)

A bundle we author (EmbbContainer(paths, payloads).build() + BndlManifest("Bundles/Types: WorldQuest").sync_from(...), verify_pair ok), served by Live VFS from mods/live-custom/files/ under NEW paths (bundles\sowce\sowce_fx.bndl -> fx\sowce\sowce_boom.fxp), is loaded by the engine's own registry: manifest read, content loaded, the effect registered BY NAME as a type-48 resource with data — and fired on the catapult impact (user: "I believe so"). live_bundle_load accepts a path no archive ships when GetLooseFilePath resolves BOTH .bndl and .embb to a live mount (source: live_vfs).

  • An effect REFERENCE never loads anything. Pointing AOEFX at a new loose path — even one live_vfs_resolve confirms is served — created no resource at all. The FX system FINDS resident effects; only a bundle (or startup) makes them resident. Loose .fxp delivery is out.
  • A MALFORMED EFFECT STALLS THE ENGINE'S RESOURCE LOADER UNTIL RESTART. A forge-rebuilt effect (Grond explosion re-tinted + a grafted SceneRender node; fx_validate OK, 21 nodes) was refused by the FX parser (resource data null, refs 4) and every later load then hung — our next custom bundle AND a shipped cloak that had loaded in 0.25 s. A MISSING file is benign; a MALFORMED one is not. The files are in Archive/live_custom_rejected_20260925/. CAUSE FOUND 2026-10-20 (emulation of the game's own loader, aire/formats/clientfx_engine_check.py): every .fxp ends with a u32 = the count of the database's (u32, u32) pair table (db+0x68, 0 in 968/968 shipped effects); the forge never wrote it, so the GADB body reader 0x4B9B50 read 4 bytes past end of file (0x4B9C60). With the 4 bytes added: accepted, 21/21 nodes. (LEAD: on the raw async stream vt 0x1E71010 a read at EOF never returns - the stall.) **CORRECTED too: categories ARE sorted
  • by the engine's StringHash(path) (371/371; header word 5 = that hash, 1,915/1,915; the loader binary-searches them, 0x115B4D4), and the forge's descriptor runs were cut by FxpEditor.run(). All three fixed in scripts/fxp_forge.py; the AIRE composer is aire/vfx/compose.py. Guard (2026-10-20):** live_bundle_load runs the game's own .fxp loader offline on every custom effect whose header shape never loaded in game (fx_structures_proven.json), and refuses only a rejection (engine_rejected). allow_unproven_fx=True skips the check. Composed effects (nodes from several donors) are now safe to ship when the check accepts them - see "VFX Studio".

Creature bundles — CharacterBundleMgr, what decides which creatures exist (MEASURED 2026-10-05)

CharacterBundleMgr (CharacterBundleMgr.cpp) = [base+0x26FFAB0]+0x868 (the owner's vt 0x1F68920 is labelled "TimeManager" in the manager table - doubtful). It owns which creature MODELS are in memory. Read live + static; one recorded fast travel (Nurnen -> Lithlad).

+0x00 entries, +0x08 u32 count (146 = Server/NPCBundle records), +0x10 category check
  entry 0x30: +0 NPCBundle rec, +0x08/+0x10 vector<CResourceBundle*> (vt 0x1E6E678, the SAME
  objects as the file registry - an entry HOLDS references to its .bndl files), +0x28 loaded
+0x18/+0x20, cap +0x28  queue {rec, u8 unload}          +0x30 current WorldInfo record
+0x38 always set (Nemesis, Playerskin_Talion)            +0x50 world set   +0x68 override set
+0x80 extra set (Playerskin_DarkTalion)                  +0x98/+0xA0 two override LIST slots
+0xA8 provider = _StructuresWorldInfoBundleData primary   +0xB0 dirty byte
  • Update 0x4B4FFC: when dirty, wanted = expand(first override list, or default) + the always/ extra sets; world set = expand(provider's list); reconcile 0xE9F360 = request what is new (RequestBundleLoad 0x4B6204), queue what dropped out for unload; then drain the queue, firing loaded/unloaded events through the global script agent (GM+0x6CF0).
  • A list's size is its field DESCRIPTOR's element count, read by 0xE9EA30: every Server/NPCBundle/Lists record has 2 fields (bundle array 0x7AB8B862 + an empty second array), so header byte 0 = 2. World_Island_Day 6 (Goblin, Spider, Warg_Base, Fellbeast, Troll_Base, Troll_Poison), World_MinasIthil_Day 9. Vanilla keeps a region's whole creature set loaded for the visit. There is no engine picker.
  • A region change resets everything: every set and every loaded creature bundle cleared, on-demand loads included; then rebuilt (skin set first, then the world set, ~3 s to resident). Direct RequestBundleLoads persist WITHIN a region (no set owns them, so no reconcile drops them).
  • Spawn gate 0x16652C (template -> model -> NPCBundle -> IsBundleLoaded 0x1665B4): a missing bundle is requested ONLY when the region's WorldInfo.IsTestWorld is set (0x5B85B4); retail regions have it 0, so the spawn is REJECTED ([AI|SPAWNAMBIENT|REJECT] ... doesn't have character bundle loaded). Do not flip IsTestWorld: 0x5B813C (28 callers) skips test worlds in its world lookup, and loading screen / telemetry read it too. Disassembled from the shipped exe (2026-10-05): desc = ResolveCharDesc 0x166878(rdx) reads ONLY the template + SpawnManager (SM+0x78 per-template override table, SM+0x80 count, SM+0x88 the AI/Templates category - a foreign record asserts); rcx is never read. Then GetCharacterModel 0x16680C / GetCharacterBundle 0x166680 (plain field getters); a NULL bundle = spawn allowed (94 of 177 templates: every orc/olog class, tamed wargs, FellBeast - always-resident data). The chain called live with rcx = 0 from the main thread matched the GADB read 6/6 (Gondorian_Soldier -> Gondorian_Soldiers, MaleCivilian -> Gondorian_Civilians, AI_Talion -> DLC_AI_Talion, Balrog -> Balrog, Orc_Defender / FellBeast -> none).
  • Memory accounting (the engine's own, read-only): CResourceBundle slot 6 (0x6E001C) = {loaded, total, bytes}, memoized at +0x60 flag / +0x64 / +0x68 / +0x6C once complete; bytes = sum of u32 res+0x38 over content [bundle+0x18] vector +0x20/+0x28 plus the first [content+0x18] entries of vector +0x00 (0x6E00CC + cold 0x112931A). Mirror matched the engine's cached value exactly (1,099,088). Lithlad: Nemesis 234 MB, player skins 205 MB, Warg_Base 48 MB, Troll_Base 30 MB, Easterlings 23 MB, Fellbeast 17 MB; all loaded 570 MB.
  • WorldInfo.MaxBundleSizePC (1096 retail, consoles 548, VerifySizeOnPack) is a PACK-TIME budget: no runtime code reads it (control: IsTestWorld has a cache slot + 90 code users; these have none).
  • Bundle loads do NOT consume low address space (MEASURED 2026-10-05, 2 loads via RequestBundleLoad on the main thread, idle noise 0): Balrog 15.2 MB engine-accounted -> +30 MB commit; Nazgul_base 36.0 MB -> +120 MB commit and +120 MB dedicated VRAM; both resident 3.5 s after the request; below-4 GB free (43-44 MB, largest hole 2.2 MB) unchanged. Real GPU cost is ~3x the engine's byte count, so a budget must use MEASURED deltas, not res+0x38 sums. On this PC the game holds 6.35 GB VRAM in Lithlad (24 GB card).
