Live world objects — bind, move, summon (PROVEN IN-GAME 2026-09-24)

Any loaded, named world object can be relocated live through the engine's own GameBase:CopyXForm (0x1823B70 = SetPosition 0x1454EC + SetRotation 0xEF690), run on the main-thread poller. No hook, no file, no raw write to the moved object. User-confirmed in order: a street bench on Talion's rooftop; a barrel brush that arrived SOLID, bow-targetable and destructible; then all 46 wasp-nest prefabs in Minas Ithil (782 objects, 0.6 s) hanging in rings around Talion, swarms live, shooting them working in place.

  • One object-name table PER WORLD CONTEXT (vt 0x1DB5D58, 32 live: main world 66,594, lighting 3,194, ambientpostfall 2,418, t1/t2 prop sets, player-spawned 381, UI scenes). Every placed object holds [obj+0x58] = its context; names hang at [ctx+0x68] (0x800 buckets x 0x18, hash & 0x7FF, node at obj+0x28: +8 next, +0x10 hash, +0x18 char*).
  • Class.Create(scriptId, name, b3, relative) (0x5013A8 -> 0x501B64) resolves name in the scriptId's OWN context only; a miss or class mismatch returns Class.None (no fault). scriptId = {PrefabName, PropertyName, Instance}; Instance is a WEAK handle (payload udata+0x20, instance at +0x48) that goes NULL when the prefab's cell streams out. Live scriptIds are harvested from suspended engine coroutines (debug.getregistry() + debug.getlocal).
  • Only 117 of 125 classes use that generic Create. AINavMeshObstacle, AINodeAbstract, AINodeSet, ParticleSurface, Prop, QuestRelay, ScriptTimer, TeleportPoint were not verified generic and ScriptObject.Create is 0x501CAC. The main thread has NO SEH — never call a Create outside aire/data/live_objects/generic_create_classes.json with the 4-arg shape.
  • Collision follows ownership. CopyXForm moves render + any physics the object OWNS (setter path 0x274C3C forwards to the body at obj+0x98). .WM DOG brushes (vt 0x1DBD570, 607/634 own pieces) and cage brushes (0x1FA3C00, 84/84) arrive solid. 97% of FireProps (bench, barrel stacks) own NO pieces — their collision is baked in the section's static PhysicsBSP, so they move walk-through.
  • A destructible prop is a PREFAB. Moving only the brush left .CE/FX behind: the arrow broke it, the sound played, no explosion at the new spot. Move the whole <prefix>.* group.
  • Arbitrary coordinates go through markers — TeleportPoint-class objects (vt 0x1DC9C38, ~270 loaded) whose transform is raw-written (vptr checked, journaled), CopyXForm'd onto, and restored byte-exact (verified 270/270 after the summon).
  • Moves are live state: they revert when the cell re-streams; nothing is saved.
call("live_objects_scan")                                  # directory (bindable contexts)
call("live_objects_find", pattern=r"\.WM$", limit=20)      # nearest, live-verified
call("live_place", name="Barre_40.WM", offset=[-250, -60, 0])
call("live_place_group", prefix="WaspN_16", offset=[0, 150, 500])
call("live_summon", family="WaspN", radius=600, spacing=350, height=200)

Modules: aire/pipeline/live_objects.py (directory, binding, single moves), aire/pipeline/live_groups.py (prefab groups, summon). Summon RELOCATES the world's own prefabs; live_clone (below) creates NEW ones.

Live clone — TRUE spawning through the engine's object factory (PROVEN IN-GAME 2026-09-24)

New world objects, built by the engine's own factory on the main thread, while the game runs. No hook, no file, no memcpy. User-confirmed in order: a cloned crate beside Talion; a cloned barrel brush (visible once its flags byte was copied); then the whole grog-barrel prefab Barre_169 — 48 objects, a NEW barrel the player can poison for orcs to drink; then 12 new wasp nests (204 objects, 0 faults).

Main-thread native bridge (the enabler). The main VM ships package.loadlib (0x1D17020 -> worker 0x1D0DEC0 = IAT LoadLibraryA 0x1D92228 + GetProcAddress 0x1D92220 -> pushcclosure 0x1D09E00; failure returns ZERO values). The main-thread poller loads the framework export sowce_native(lua_State*) (sdk/sow_main_native.cpp, in the SHARED target — a static-lib export is dropped by the linker) and calls it inside the engine's own script tick: measured main tid=<first thread> mainvm=1. Every engine call there is SEH-guarded (main-thread LUA has no such net); call is refused unless L+0x10 equals the main VM's global state. Args are hex STRINGS (HavokScript numbers are float32). lua_pushstring = 0x4082D8. AIRE: aire/pipeline/main_native.py (live_native_ping/_read/_call). A running process keeps the OLD dll (LoadLibrary returns the loaded module) — a rebuild needs a restart.

The engine path. - ObjectServer [base+0x26FF058] (vt 0x22C0B28, LithTech ILTServer lineage): vt[8] 0x43D630 = CreateObject(template) = copy 0x43D680 + creator + post-create; vt[14] 0x502034 = find by name; vt[4] drives the time-sliced ObjectSet streamer 0x43DBC8. - Creator 0x1CD454(_, CObjectCreateParams*) — also what the batch loader 0x11B4EC0 calls. Allocates from the class holder, runs the ctor, ReadProps (vt+0x60), sets the transform, registers the name, links into the ObjectSet, builds components (vt+0x68), activates (vt+0x80/+0x70/+0x48). - Class descriptor [[obj+0x78]]: +0 name, +8 parent, +0x18 placement ctor, +0x20 dtor, +0x2C object size; 304 classes in the static table at 0x2A61E48. - CObjectCreateParams (defaults 0x43DAA0): +0x01 flags -> obj+0xE2 (bit0 visible, 0xC solid; FireProp's ReadProps fills it, a DOG brush's does not), +0x04 pos, +0x10 scale, +0x14 quat, +0x30 -> obj+0xD4, +0x34 -> obj+0xD8, +0x40 class holder (obj+0x78), +0x168 inline name (interned), +0x188 name ptr (0 = use +0x168), +0x198 ObjectRec — the object's record in the layer's ObjectPropertyDB (obj+0x50; ReadProps pulls every property from it), +0x1A0 ObjectSet (= the world context, obj+0x58). Loader entries (0x50 B): +0 holder, +8 name, +0x10 word, +0x18 index, +0x1C pos, +0x28 quat. - Render + collision are bound BY NAME. vt+0x68 -> 0x333430 asks the set's resource table (set->vt+0x28 0x3334F0, table set+0x98) with key obj+0x40 = the registered name. A clone under a NEW name is created but draws nothing; a clone under its SOURCE's name gets the model and physics. Duplicate names are legal — insert 0x115ED3C appends, lookup 0x4DC078 walks from the tail — so the newest node answers: a cloned DOG binds the cloned brushes and states during post-create. - A prefab clone mirrors the batch loader: create EVERY member (one main-thread chunk), then post-create (vt+0xA8) each (a second chunk). ScriptObjects/StartupCommands are skipped by default (they would run the prefab's scenario Lua again). - Clone copies ONE AT A TIME. Because the newest node answers a name, 12 nest copies cloned in a single batch all bound the LAST copy's DOGS_Alive (measured: 4/4 DOGs shared one state object, 1/6 brushes linked) — meshes drew, nothing reacted. Completing each copy (create -> post-create -> DOG state) before the next exists keeps every copy wired to itself (3/3 DOGs with their own state objects). - A cloned DOG must be put in its initial state. The DOG post-create (0x4871190) collects its 32 state links (DOG+0x190) but does not ENTER one — a streamed set gets that later, a clone never does. Brush +0x148 = its current DOG state object; null = hits route nowhere. 0x5ADF0C(dog, StateType record) is DynamicObjectGroup:Script_SetState's body (ready flag +0x22C set -> queued at +0x160, else immediate 0x5AEABC); the record is the SOURCE DOG's current state (dog+0x188 -> state object +0x180, e.g. Alive). With it the cloned nests drop, swarm and explode when shot (user-confirmed). - A lone DOG brush clone is invisible unless params[1] = the source's obj+0xE2 flags — its ReadProps does not fill them (FireProp's does). - The player's position point is ~90 above the feet (a grog barrel anchored at player-60 floated ~30); live_clone measures offsets and rings from the feet. - Clones live in the source's ObjectSet and die with it when the cell re-streams.

Live storm — projectiles from the sky over the whole area (PROVEN IN-GAME 2026-09-24)

ce:ExplodeAt(x, y, z) (stub pops 3 numbers; impl 0x1A4E604, floats in xmm1-3) detonates any CombatExplosion at coordinates — 24 BarrelStack_Fire blasts around Talion, user-confirmed. CombatExplosion payload = the record at CE+0x170 (BarrelSingle/Stack_Fire, *_WraithFire, FirePit_NormalFire, Barrel_Broken_OilSpilled, WargCage_Knockback).

CombatProjectileEmitter (vt 0x1FAC3F0): FireProjectile 0x1A4E91C fires item [e+0x158] (SetItemOverride's slot, stub 0x1BABDE8 = just that store) else [e+0x150], at target object [e+0x180] + base [e+0x188..0x190] + random [e+0x194..0x19C]. The loaded ProjecB_*/ProjecS_*.CPA are Emitter_Arrow_Barrage arrow-rain emitters. live_storm (aire/pipeline/live_storm.py) hangs every targeted emitter over its own cell of a disk, shares the target markers at one centre (identity rotation, so offsets stay world-axis) and fires them in waves — 1,280-1,536 projectiles per run, user-confirmed across the area.

  • Aim at each cell's GROUND. A projectile resolves AT its aim point and has a max travel: aimed at the player's rooftop height they hung mid-air over the streets; aimed 30 m below they burst mid-air. Ground per cell = 15th-percentile height of ground-placed objects in the directory (AI nodes 0x1DB0478/0x1FB8328, nav obstacles 0x1DCB420, spawner placements 0x1DC5800); emitter = ground + height, aim = ground - 60. Worked.
  • Flight is GADB data (Inventory/RangedWeaponData, live-editable via set_field): AI_TrollFire_RangedWeapon ships velocity 15000, LifeTime 1, MaxRange 10000, ShowModelWhileTraveling False (the rock is INVISIBLE in flight), and AOEOnRemoveNeverStopped = its impact AoE (a flight that expires detonates mid-air). Set 3000-4000 / 12 / 60000 / True for watchable 60-150 m falls.
  • ProjectileFX (String2, tc 68) is the in-flight trail — a heap char*; Anvil shows it empty because a PATCH GADB fills it (live: graug_rockthrow_projectile_fire.fxp). Repoint the cell at a resident FX's string (fx\weapons\grenades\grenade_fire.fxp, the orc fire grenade) — journaled in aire/data/live_objects/storm_string_journal.json.
  • A payload is visible only if its FX is RESIDENT — check by name with call("live_resource", paths=[...]) (below), never by guessing. Payloads that rendered in Minas Ithil: Emitter_Arrow_Barrage, PS_Fire_Arrow, Orc_Grenade_Fire, AI_TrollFire_RangedProjectile, Mounted_TrollFire_RangedProjectile.
  • Emitter_Graugapult_Barrage is a WARNING MARKER, not a weapon (CORRECTED 2026-09-25): Model/Weapon_Invisible, no fire FX, and AOEOnImpact / AOEOnRemoveNeverStopped both NULL — it raises the Graugapult HUD icon and does nothing else, loaded bundles or not (user-confirmed twice: icon only). The real catapult weapon is Troll_Graugapult_Fire (velocity 850, gravity 10, impact Combat/AOE/Graugapult_Hit_Fire = 4 ticks, only Graugapult_Hit_Tick_Fire_Inner carries a visual: AOEFX slot 10 = fx\weapons\graugapult\graugapult_explosion.fxp). The old line here — "the explosion depends on bundle-only materials, so Minas Ithil gives audio + shake and NO visual" — was WRONG: live_resource shows the explosion, both fire-trail effects and their materials RESIDENT with live references in Minas Ithil (the region ships catapults; the trail material is held by minasithil.bndl). The troll firebomb carrying Graugapult_Hit_Fire renders the real catapult explosion.
  • LEAD: a sustained storm renders its FIRST wave and then only the gameplay side (damage, audio) — consistent with a ClientFX instance budget; stagger fire to stay under it.
call("live_storm", item="AI_TrollFire_RangedProjectile", radius=7000, height=15000,
     waves=40, follow_every=10)
call("set_field", category="Inventory/RangedWeaponData", record="AI_TrollFire_RangedWeapon",
     field="AOEOnImpact", value="BarrelStack_Fire", value_category="Combat/AOE")
