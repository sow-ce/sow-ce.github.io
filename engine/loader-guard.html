Framework loader — the SoW:CE boot launcher (IN-GAME CONFIRMED 2026-10-23, the dev launcher's Play)

User 2026-10-22: wanted a loader "not connected to the game's inner workings or the standard proxy method", then "a full one click installer + play from the launcher with a visual indicating ... our modded framework or vanilla". Framework loader — winhttp.dll proxy (IN-GAME CONFIRMED 2026-10-06; the fallback since 2026-10-22)

The framework is loaded by x64\winhttp.dll (framework/sowframework/proxy/winhttp_proxy.cpp), not the bink2w64.dll proxy. ShadowOfWar.exe lists winhttp.dll in its PE import directory (live IAT binds 12 WinHttp*), it is not a KnownDLL, and it is not a game file - so Windows takes our copy from x64\ at process start, Steam "Verify integrity" never removes it, and nothing is renamed. - 70 forwarders to \\.\GLOBALROOT\SystemRoot\System32\winhttp.dll (winhttp_exports.inc, generated by gen_proxy_exports.py; a bare winhttp.X forwarder would resolve back to the proxy). Live check: all 12 game IAT slots point into System32's winhttp.dll. - Boot code shared with the bink proxy: proxy/sow_proxy_boot.hpp. bink2w64.dll is the vanilla codec again (clean run IN-GAME CONFIRMED 2026-10-07: modules = our winhttp.dll, System32 winhttp.dll, genuine bink2w64.dll, sowframework.dll). SoW:CE loads through winhttp.dll ONLY (user rule 2026-10-20: Steam's bink2w64.dll is a game file): xmake still builds the bink proxy, nothing deploys it, and the launcher has no fallback - when another mod owns winhttp.dll the framework does not load and the deploy logs that as an ERROR. An OLD SoW:CE bink proxy is retired by the launcher deploy(), the tester setup and the package install/uninstall.bat alike: only our file (marker), only from a parked bink2w64_.dll PROVEN to be Steam's codec (its SHA-1 equals Steam's depot manifest's; no readable manifest = refused, Steam Verify instead; the .bat files compare certutil against the SHA-1 embedded at package time), staged copy then ONE rename. Another loader's bink2w64.dll is never touched. The plugin-host shim x64\plugins\sowce_bootstrap.dll (a third load path: community plugin loaders AND the framework's own Community Mods auto-loader loaded it) is retired the same way (2026-10-20): xmake still builds it, nothing deploys or ships it, the loaders skip it, and old copies move to sowframework\legacy\. sowframework\logs\proxy_<slot>.txt says which one booted. Ours carry the string SoWCE-proxy (old bink builds: SoWProxy); the installer, launcher and xmake never overwrite a winhttp.dll without it. - tests/test_proxy_exports.py checks both proxies' export coverage against the real DLLs (the RIP=0 crash class). - The exe's outer wrapper is SteamStub 3.1 (.bind section, entry 0x73D1310, original entry 0x72A5000), flags NoModuleVerification | NoEncryption. Patching the exe instead was rejected: same load timing as an import-table proxy, breaks WB's Authenticode signature, undone by Steam Verify.

Vanilla Guard — SoW:CE leaves no change in the game files (RAN ON THE DEV INSTALL 2026-10-20)

User rule: "Nothing SHOULD EVER modify game files and keep them modified." Two halves: no tool writes the install (see the PRIME DIRECTIVE rule), and the loader proxy undoes SoW:CE's past changes at every launch, before the engine opens a file - whatever started the game.

SCOPE: SoW:CE ONLY (user, 2026-10-19: "this is ONLY pertaining to SoW:CE nothing else"). Undone by default, nothing else: - default.archcfg lines that are exactly ..\Mods\armory.Arch06 / ..\Mods\sowce_*.Arch06 (taken out) and ..\Mods\zz_modkit_<tag>_<Base>.Arch06 (the vanilla <Base> line given back; when that line is unknown the modkit line is KEPT and reported, never guessed); every other line kept byte for byte, so a Nexus mod's lines stay. The Armory line stays while the hotchunk keeps an Armory build (they belong together: records pointing at an unmounted archive); - hotchunk.arch06 ONLY when it is byte for byte a SoW:CE build: a known SHA-1 (d759d4c5..., the dev install of 2026-10-08) or the tester setup's installed.json Armory record (size AND SHA-256). An Armory archcfg line alone is not enough (another tool may have changed the same file too), and never when hotchunk.arch06.giant_uruks.json exists (the Giant Uruks tool owns its twins, with its own Remove; saves name those records); - the 5 dev console leftovers under game\, matched by size + SHA-1 (a Nexus console mod may ship the same names); - SoW:CE's OLD loader in x64\bink2w64.dll (marker): the game has it loaded at boot, so the boot guard only reports it (LATER, verdict PENDING); the launcher / tester setup / vanilla_restore put Steam's codec back with the game closed. Everything else - another mod's archives, archcfg lines, loose files, a missing shipped file - is logged LEFT and never touched. mode=strict in x64\sowframework\config\vanilla_guard.txt (or VanillaGuard(mode="strict")) puts EVERY file back to Steam's, the behaviour described below. Verdicts: RESTORED - SoW:CE's changes undone, CLEAN - nothing of SoW:CE's in the install; N change(s) by other mods left as they are, VANILLA, PENDING (only the loaded old bink proxy is left; undone with the game closed), SoW:CE CHANGES LEFT (needs Steam Verify), REPORT ONLY.

The authority is Steam's own depot manifests, never a backup name. steamapps\appmanifest_356190.acf InstalledDepots names the installed manifest per depot (build 3095001: 356191 -> 8564100506276968089, 561650 -> 6461386082584988817, 533110 -> 3372049505845498644); <Steam>\depotcache\<depot>_<id>.manifest = u32 0x71F617D0 | u32 len | ContentManifestPayload (protobuf; FileMapping 1 filename with \, 2 size, 3 flags 0x40 dir / 0x200 symlink, 4 sha_filename = SHA-1 of the lower-cased path 793/793, 5 sha_content = plain file SHA-1 7/7), then 0x1F4812BE | len | metadata (4 = filenames_encrypted). Parser aire/formats/steam_manifest.py.

THIS IS USEFUL — Steam's LastUpdated marks what to hash. acf LastUpdated = 2026-09-22 23:55 (the Steam Verify). Exactly 2 of 901 files have a later last-write time, the same 2 the full sweep found. Boot guard (proxy/sow_vanilla_guard.hpp, from OnProcessAttach in proxy/sow_proxy_boot.hpp, both proxies; loader-lock-safe Win32 only): size-check all files; SHA-1 hotchunk + archcfg + every file <= 1 MB + every file written after LastUpdated (10 min slack) unless x64\sowframework\vanilla\verified.tsv (size\tfiletime\tsha1\trel, shared with Python) knows that size + last-write time; then (strict mode: for every bad file; default: for SoW:CE's, per SCOPE above) restore each file from a source whose size AND SHA-1 are Steam's (the store x64\sowframework\vanilla\store\, a sibling <name>.*, or for the archcfg the embedded proxy/sow_vanilla_archcfg.inc, itself SHA-1-checked) - staged and verified, the old file COPIED to x64\sowframework\vanilla\quarantine\<stamp>\, then ONE MoveFileEx(REPLACE_EXISTING | WRITE_THROUGH) (Python: os.replace) - the game file is never missing or half written, and a locked file is left exactly as it was (tested); foreign files under game\, x64\game\ and archives the vanilla archcfg names (e.g. uhdmip.Arch06) moved to quarantine; Steam-verified copies of hotchunk + archcfg kept in the store. Nothing is deleted. A file with no verified source is left and reported ("use Steam Verify integrity"). No complete manifest / encrypted names = report only, no action. Log x64\sowframework\logs\vanilla_guard.txt (rewritten each launch; it names the loader slot), and a run that changed something also keeps its log as quarantine\<stamp>\vanilla_guard.txt; diagnostic switch x64\sowframework\config\vanilla_guard.txt containing mode=report.
