Save files — SOM3 DECRYPTED (MEASURED OFFLINE 2026-09-29)

Steam saves: Steam\userdata\<acct>\356190\remote\<acct hex>_<slot>_ShadowOfWar.sav — the file prefix IS the Steam account ID in hex (<account id hex> = , the userdata folder).

header  'SOM3' | u32 salt | u32 padded_len (= file - 16, %16 == 0) | u32 real_len
body    AES-256-CBC (EVP_aes_256_cbc: nid 427, key 32, iv 16), PKCS#7 padding
key     b'ad@210766@vac94Cd_?dVt5$alivjz$e' (const @ RVA 0x1E6CB08), then
          salt bytes 0,1,2,3 -> key positions 26, 11, 18, 17
          acct bytes 0,1,2,3 -> key positions 10, 30, 22, 2   (SOM3 only; SOM2 skips it)
iv      first 16 bytes of b'yuwgb@oftv@gx$t32' (const @ RVA 0x1E6CAF0)

Reader 0x119A2C8 (accepts SOM2|SOM3: sub eax,'SOM2'; test eax,0xFEFFFFFF), writer at 0x52B4BC; OpenSSL EVP: CTX_new 0x8C5350, aes_256_cbc 0x8C7D10, DecryptInit_ex 0x8C59C0, set_padding 0x8C5460, DecryptUpdate 0x8C59F0, DecryptFinal_ex 0x8C5810. The account value is read from obj+0x868. Verified: pad byte 3 == padded_len - real_len; plaintext opens SAVE v2 then chunk tags (GOXC, DIFF, INVA, CBTC, GCPT, QSTD, IVSH, FAST...), entropy 8.00 -> 5.01.

Records are serialized as P=919 NAME HASHES, not name strings. 421 ASCII tokens in 2.3 MB, all settings; Faction_/Quirk_/Orc_ strings = 0. As u32 hashes: Captain 321, Faction_MtnPass 262, Marker_Potential_High 141, AI_Defender 116, Orc_Defender 115, TribeDef_Machine 74; controls absent from the save (Broom, Warg_Tamed) = 0. So "the game serializes record NAMES" holds only in hashed form — a name hash is category-agnostic, so the serializer's context decides which category a hash means. Write-back (re-encrypt) is untested: any inner checksum in the SAVE header is not yet known.

Plaintext layout + the front-screen card (MEASURED 2026-10-15, matched to the game's own screen). SAVE v2 header (u32 profile-section count at +0x18 = 5), the profile sections, u32 slot count (3), then per slot {u32 6, u32 length, u32 0, payload}. A section = tag, u32 ver, u32 size, u32 0, u32 n (= size - 4), n bytes of TYPED values: 00 P919 hash, 04 int, 0a float (4 bytes), 0c bool (1 byte). A slot's payload opens with its summary section (SAVE v31, 10 values: region, -, hash, completion % (DOUBTED 2026-10-28: 100.0 in the save while the card showed 75 % - see "New Game+" below), play-time MINUTES, int, bool, 3 hashes). The menu card sub_DF9370 (slot info [CGameClientShell+0xEB8] + 0x1C8 + GameModes.SaveSlot * 0x298) prints ceilf(+0x24 minutes) as PROG_PlayTime "{1!d}h {2!d}m" and floorf(+0x20) as PROG_PercentComplete "{1!d} %"; for a GameModes.UseHighScore mode (DLC4) it prints instead (int) the score of sub_FAD1B0([0x2A36278], mode) = first entry with +0x80 == mode and +0x50 != 0, score at entry+0x68. Those entries are the profile section GMSC (writer sub_FAE990, loader sub_FAD530): per mode {mode, int, session sub-object, score record A -> +0x08, record B -> +0x40, bool}, record = {mode, hash, 5 ints, 4 floats, bool}, score = its 2nd float. Dev save: 12514.54 min -> "208h 35m", 443.29 -> "7h 24m", 777651.94 -> 777651, all three as on screen. GMSC is NOT a last-played marker (the 2026-10-13 reading); nothing seen in the file names the slot played last. Readers: launcher/tester_setup/setup_saves.py summarize and its twin Summarize in sdk/sow_save_backup.hpp (36/36 saves identical).

The engine's own save switch: GameModes.CanSave on the CURRENT mode (MEASURED 2026-10-16, static + live values; switching it in game NOT yet run). Both world-save paths read it live and skip the save when it is clear: the save task vt_0x1F6CC40::vf3 0x52C70C -> 0x52C664 (also refuses on [CGameClientShell+0xE38] state, flags +0x189/+0x194, [CGCS+0xA20]) -> accessor 0x52C5EC, and the world save 0x5B7B58 ("Attempting to save the game without a world to restore") at 0x5B7BA8. Current mode = [base+0x2A36260] (signature CurrentGameMode; SinglePlayer in the campaign). CanSave = packed bool 13 of cell 0 (single-bit RMW). Shipped clear on QuestReplay (story mission replays) and Benchmark - the engine is built to run a world that never saves. SaveCurrentWorld (bit 3) is a second gate inside 0x5B7B58. The SOM3 writer (0x52B1CC, entered by tail jump from 0x52A4B0, address-taken by 0x119A0EC) is a platform callback downstream of both. Used by the Orcs > Randomize > Nemesis Chaos "Chaos Sandbox" (ui/tabs/sow_nemesis_chaos_engine.hpp SaveGate) - the clean way to keep a live mod's in-world consequences out of the save without a hook. One owner-counted gate for every user of the cell: sdk/sow_save_pause.hpp (2026-10-19, built, cl /Zs clean, NOT run in game). Two independent gates on one cell break each other: the second records false as its "original" (the first already cleared it), and when the first lets go the second "restores" false - saving off for the rest of the session. The gate records the original once and restores it only when the LAST owner releases; it re-reads the GameDB generation first, so a rebuilt table is never written through old addresses. Owners: Nemesis Chaos (its SaveGate is now a thin wrapper) and the world roll = every Engine-tab run - Dashboard SAFE WORLD ROLL, Engine-tab SAFE shuffles, ladder levels, presets, RANDOMIZE and each Auto-Chaos tick ("Keep my save clean", default ON, user decision 2026-10-19): paused before the run's first write, re-paused after a load, and ended at the title screen, which also REVERTS the edits (and stops Auto-Chaos), or by an explicit "Resume saving..." confirmation (Dashboard and Engine tab).

Save slot contents - the typed grammar, the 27 sections, the story gate, the inventory (MEASURED 2026-10-28)

Offline, on a decrypted in-memory copy of the dev's <account id hex>_ShadowOfWar.sav of 2026-10-28 (2,432,928 B file, 2,432,898 B plaintext; the real file only read). Research scripts: session scratchpad (savetok.py, ngp_gear3.py); the framework reader is sdk/sow_save_slot.hpp.

The typed-value grammar has ten tags, not four. 00 P919 hash (4 B), 02 u8, 04 u32, 05 two u32 (a GUID half, a pair of counters), 08 i32, 0A f32, 0C bool (1 B), 0E vec3 (12 B; in PDIC a world position in cm, e.g. (-41977, 23154, -29368)), 0F byte string (u8 length + bytes: GUID text, a loot product id), 10 u32 (the byte size of what follows: IVMG 10 29427). With these ten, 27 of 27 sections of the story slot read to their exact end (REEL is empty). SectionValues in sow_save_backup.hpp still knows only 00 04 0A 0C; it reads the summary and GMSC, which use no others.

Layout. 86 typed sections = 5 profile (GOXC PERF PICB GPDC GMSC) + the same 27 in each of the 3 slots. Per slot, in file order: SAVE(summary, v31), one u32 = the byte length of the rest of the slot (0x16A537 here: the slot header's length minus the summary and itself), IVGD(v3) ENT2 IVSH PPDC PDIC PAIC IEUC IVMG(v43) IVPD(v4) TTRL LTMR (back to back from IVGD on), then about 1.28 MB with no typed section header (meaning not read), then FAST FOTP ASMC DIFF CBTC GCPT INVA REEL QSTD(v23) PDCC LPDC AUDI IIUC UITC STOR(v159). Most sections open with 04 3, 00 P919(<game mode>) (SinglePlayer in the story slot: IVGD, PPDC, PDIC, IVMG, IVPD read). Which section holds what, by the record hashes inside (story slot): IVMG 787 Inventory/Items + 197 Inventory/Affix/Definition hashes; IVPD 581 items (PS_*, S_*); IVGD 57 items + the variables; IIUC 40.

IVGD = the GameData variables (the store at [GM+0x6C58], see kb/quests-story-scenes.md): 04 3, 00 mode, 10 size, 04 573, then 573 x 00 variable hash, 02 VariableType, value with the value 08 i32 (type 1, int), 0C u8 (type 2, bool) or 0A f32. The list occurs three times in the story slot's IVGD. The FIRST copy holds the played values; the other two hold the record defaults on this save:

Control: StoryState = 300 is also what the 2026-10-01 live read gave on this save line (kb/quests-story-scenes.md). What copies 2 and 3 are (checkpoint / restore states?) is a LEAD. StoryState's own Description: 5 Intro, 100 Start of Act 1, 105, 110 After Gondor 1, 198 / 199 Blade 1, 200 Start of Act 2, 205, 210, 230 After Carnan 3, 290 During Finale, 300 After Finale. The Shadow Wars have their own variables: NeedShadowWarTut, ShadowWarTutDone, PostShadowWar (no Description).

PPDC = the per-mode level / XP table (sow_player_progress.hpp, [GM+0x6D20]): {00 mode, 04 level0, 04 XP}; this save SinglePlayer 79 (= level 80) / 51417.

IVMG (v43) = the player's inventory. In order: 1. header 04 3, 00 mode, 0C, 10 size, 05 (1871, 9597), 00 PlayerSkin00, 04 11515, 04 729, 0C 1 (11515 is one above the highest saved item id; that it is the next-id counter is a LEAD); 2. 714 owned stacks {00 item, 04 count, 04 ?, 04 n, n x 04, 0C}. 714 is also the live vc+0x740 count in aire/documents/INVENTORY_SYSTEM_DECODE.md. PC_Mirian count 2,605,912; Runegem_* 13 stacks, 93 gems. Unlock and flag items (Tutorial_*, Apdx_*, S_*, PS_*, ScriptedUnlock_*) are stacks too; 3. 14 bools, then 04 75, 0C 1, then gear item records: 04 id, 04 level, 02 0, 00 Inventory/Items, 00 visual (EquippedWeaponData), 00 0, 0C, 0C, 04 n, n x 00 Affix/Definition, 04 0, 05 GUID lo, 05 GUID hi, 0F source product, 02 0, 0C hasNemesis, then the optional nemesis block (00 NemesisGear, 00 Description, 00 Role, 04 seed, 04 seed, 0C, then optionally upgrade tier / art / challenge Combat/Challenge/Eval + progress + weighted Faction/Loot/Tag list) and two closing bools. 71 of the 75 declared records match that fixed prefix, all of them Inventory/Items; levels L1 x5, L6, L79, L80 x63, L85; sources mithril chest 36, gold chest 6, none 29. The other 4 are ids 11511-11514, seen only in the slot list below (body slots: LEAD). The nested-block layout is read from two variants only (LEAD); 4. 04 25 + 25 x {0C, [04 item id]}: one per inventory slot (25 = the slot-vector count). Reading it as the equipped item per slot is a LEAD (not matched against a live read); 5. 04 0, 04 4 + 4 x {00 item, 04 count} (SotP_CelebrimborSet_3Bow, SotP_CelebrimborSet_6Ring, GondorCollectable_AwardSkill_BonusGems, SotP_SkinReward), then 04 0, 0C 1, 04 8 + 8 gem sockets {00 SocketType, 0C, 00 SocketType, 00 gem} (every gem field 0 on this save), then DLC3 / DLC4 bools.

IVPD (v4) = 584 x {00 Inventory/Items (PS_* / S_* skill items), 04 value} (0 or 1 seen; "1 = owned" is a LEAD).
