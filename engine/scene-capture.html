Scene Capture — the live world as a 3D file (BUILT 2026-10-06, read-only, hookless)

aire/capture/ (scene / mesh_index / geometry / textures / tint / pose / world / arrays / compose / gltf / actions). User opened the textured capture in Blender (screenshot). Nothing is written to the game.

call("scene_index_build")                      # once, offline ~30 s: every EMBB path table ->
                                               # (archive, entry, section), 190,407 containers
call("scene_capture")                          # game in world: characters (exact pieces, live
                                               # pos/rot, LIVE POSE as glTF skins = armatures in
                                               # Blender, engine tint) + named world objects as
                                               # markers -> aire/data/capture/scenes/<stamp>_<region>/
                                               # scene.glb, manifest.json, preview.png, scene.html
call("scene_capture", radius=3000, tint=True, pose=True, weapons=True, off_array=True,
     tex_size=1024, normal_size=512, spec_size=512, detail_radius=2000)
call("scene_captures")
  • Characters: SpawnManager entries (+0x20) + player [[base+0x26FFA98]+0x888]; CChar +0xAC position (= mesh origin), +0xB8 quat (x,y,z,w), +0xC8 f32 uniform SCALE (0.88-1.25 on orcs / humans, crows 1.09-1.50; the pose is unscaled model space, the engine draws pos + scale * R * t - proven through the weapons below), +0xE2 flags, bit 0 = visible (every spawned character 0x2f / 0xf / 0x3, corpses 0x27, the 255 pooled stand-ins 0x0); names via FS pools (FM+0x48 -> CChar). Captures before 2026-10-06 17:40 drew everyone at 1.0.
  • Pieces: heap census of vt 0x1FE19E8: +0x28 material-slot object (vt 0x1FFE3E8), +0x70 skeleton object (vt 0x1F6F950, = CChar+0x110, or [CChar+0x22E0]+0x60 for heads), +0x80 Model record, +0x90 inline .mesh path. Slot table matobj+0x1E8, stride 0x18, +0 = the .mat resource (resource+0x28 = path), in GADB MaterialSet order. No count field (+0x170 read 12 on an orc head by coincidence, 0 on 5-slot armour): read a 32-entry window.
  • MMSH object table (inside the descriptor block): N1 16-byte records {flags, objectId, arena (== B[i]), material slot}; an object's consecutive records are its LOD chain, arena -1 = not drawn further, LOD0 = the object's first record. Grouping on -1 instead of object id dropped Talion's face and the armour belts.
  • Textures: tDiffuseMap (hair shader: tBodyDiffuseMap + coverage tHairAlphaMap), BC1/BC3, largest mip <= tex_size. glTF: SoW -> (x, y, -z)/100, winding reversed, quat (-x,-y,z,w).

Live skeletal pose — every character in its in-game stance (MEASURED 2026-10-06)

CChar+0xA0 -> transform node (vt 0x1DA9778, 21,276 live: a generic class)
  +0x10 {f32 t[4], f32 q[4]} x N, MODEL space (root at origin), quat (x,y,z,w)
  +0x18 u32 bytes (= N*32)   +0x1C u32 N (= the rig's bone count)
CChar+0xF90 -> a second node of the class, same pose (+-0.08 cm on finger tips)
  • Bone order = the rig SKEL's NAME-TABLE order (the vertex-palette space). Rig = Model/SimpleModel.Base -> Model.ModelFile (SimpleModel = [[CChar+0x2340]+0xC0]+8; orc_anim_base -> orcs\base\orc_base.skel 100 bones, player 128, Gondorian 95, olog 89).
  • Found WITHOUT names by a bone-length oracle (rigid rig: |T_i - T_parent| = bind length in any pose): 292 heap arrays passed at ~1e-7 against 11,645 quaternion runs of the same length that do not; 290 hang at +0x10 of a vt 0x1DA9778 node. Convention: child = parent + R_p inv(Rb_p) (bind offset) holds at 0.000 cm median only with (x,y,z,w) for both live and SKEL bind quats. Live time-diffing was useless: the game PAUSES simulation without window focus.
  • Skinning: piece joints = piece SKEL name-table indices (palette[palette_idx]); per piece a glTF skin = rig nodes by NAME + the piece's own inverse binds (23 of 124 pieces bind differently from the rig, 43 carry bones the rig lacks - those ride their nearest rig ancestor rigidly). Vertex weights are stored BGRA against RGBA indices - see the MODEL LAYER entry.
  • Face: [[[CChar+0x22E0]+0x60]+0x60]+0xA0 = a node of the same class with the HEAD rig's pose (Talion 241 = his head skel, orc 134, Gondorian 136; head-piece name-table order), in a canonical head space (its Head bone reads (0, 72.8, 0.7) on all three), so face bones are re-rooted on the body's live Head: Body[Head] inv(Head[Head]) Head[b]. Oracle 3.6e-4..9.4e-3, not 1e-7, because face bones TRANSLATE. 42/44 characters, 49 head/hair pieces.
  • The body pose's root is the character position CChar+0xAC, ~1 m above the feet (Pelvis y -3..-9 live, +95 in bind). A bind-pose SKEL (origin at the feet) placed at +0xAC floats by that much; skins stand on the ground, unskinnable pieces ride the live Pelvis.
  • 44/44 posed in the last capture (55/57 the one before: 2 had no node); no cloth.

Weapons, corpses, crows — everything posed in the world (MEASURED 2026-10-06)

  • Held / sheathed weapons are not pieces. Objects of vt 0x1DAA9D0 (a generic class: 52,483 live, 311 with a mesh) name their mesh INLINE and carry their own WORLD transform: -0x30 f32[3] position, -0x24 f32 scale, -0x20 quat (x,y,z,w); +0x20 the wielder (CCharacter), +0x60 material slots (vt 0x1FFE3E8, same as a piece's +0x28), +0xB0 the .mesh path. 216 of 311 name a spawned wielder; the transform sits on the wielder's live attach bone (L_Sheath_1, Sheath_Def01/02, Sheath_Bow, R_Weapon, Shield_L, L_Weapon) at 0.1-4.8 cm and 0.0-0.9 degrees, and its scale equals the wielder's CChar+0xC8 exactly - the scale that also fits the bones (pos - P = s R t, best fit within 0.002). Render check: spear upright in the Defender's hand with the shield on his arm, torches in the Sappers' hands, Talion's sword in hand and dagger at the hip. The Weapon_Invisible pieces (1x1square.mesh, owners vt 0x1DBFFA0 / 0x1DBD850) are unrelated proxies.
  • Every skeleton object's owner shares the character's base layout (skel+0x60 = owner): +0xA0 pose node, +0xAC / +0xB8 / +0xC8 transform and scale, +0xE2 visible bit; the node's bone order is the skeleton object's own base .skel (skel+0x10 resource, +0x28 path) - oracle 1e-7 on crows (crow.skel 28), rats (19), corpses, alarm bells. So the rig needs no GADB chain off a CCharacter (PoseReader.read(owner, rig_path=...)).
  • Corpses leave the spawn array (measured in the Clone Army work, 2026-10-01) but keep their CCharacter, skeleton and pose: 23 dead (combat+0x4A0 set, flags 0x27) within 80 m in one Minas Ithil sample. off_array adds them and the other visible owners: crows (vt 0x1DBBD30), rats (0x1FA4600), signal alarms / doors (0x1FADFC0), thrown spears (0x1DAA4B0), orcs of vt 0x1FA2A38 (flags 0x21, captain-sized; class unidentified), bats, raptors, keep doors. Skipped: hidden owners (pooled stand-ins vt 0x1FABD08), the 1x1square proxies, skeletons a captured character claims, HEAD owners ([[CChar+0x22E0]+0x60]+0x60, vt 0x1DB7018 - a head skeleton's owner is never the character; taking them put Talion's head beside him), and owners sitting exactly on a character's origin (render doubles: the Dark Talion wraith double vt 0x1DBD198). A rig of <= 4 bones with no bone longer than 2 cm (landmine 1, spear 3) cannot be oracle-tested; the bone COUNT agreeing is the evidence.

World geometry — the static world the engine streamed in (MEASURED 2026-10-06, Cirith Ungol)

aire/capture/world.py + aire/formats/{prfb,wdsc,wldmsh,texa}.py + aire/capture/arrays.py. call("scene_capture", world=True, world_radius=15000, array_size=2048, array_draw_size=2048) adds a "World geometry" node. Headless Blender render: cliffs with the rust layers, the ruined watchtower with its stone courses and arches, duckboards over the mud river.

  • What is loaded = every resident .wldclnt in the live resource table ([base+0x2A86758], 0x800 buckets x 0x18; res +0x28 name; skip prefabs\ui\ = the army-menu world). 12-13 parts.
  • WDSC v9 (.wldclnt) = a part's placements: header [4] instances, [6] has-wldmsh, [7] materials, [10] string bytes, strings at 0x2C; a material block {nmat, 0, offsets[1+nmat]} only when [6] or [7]; then 76-byte UNALIGNED records {bmin, bmax, pos, quat (x,y,z,w), scale, flags, kind, hash, f32 cull, u32 prefab path offset (from 0x2C)}. Same world space as CChar+0xAC. ~9,880 placements of 334 prefabs; 828 within 150 m.
  • PRFB v8 (.inst) = a prefab's baked geometry (static world is NOT .mesh; prefab .mesh files are the destructible / animated pieces). Size triple {draws, vb bytes, ib bytes} before the vb; per draw ONE vertex block ENDING at vend, stride-aligned, stream 0 then stream 1; u16 indices idx_min..idx_max rebased by idx_min; tail = format table {stream, type, usage, index} (types 2 float3, 12 half4, 10 half2, 4 ubyte4; usages 0 pos 1 normal 2 tangent 3 binormal 4 uv 5 colour), 52-byte draw records {0, n, n, istart, base, tris, material, 0, 0, fmt, vend, f, f}, then the material paths. Positions prefab-local, pivot at the base centre.
  • LOD records from 0x38, 44 bytes, -1.0 at +28, grouped by a per-group TAG (0xD238B9DD keep wall, 0xD238B9DE human buildings, 0x3249 lanterns, 0x159a the extra leading group of fort pieces): root {tag, -1, 0, 0, next = first unit, CULL distance}, unit {tag, hash, first draw, count (0 = draws nothing at that range), next (-1 finest), switch distance, f, -1.0, 0, 0, distinct}. Engine rule per instance: walk coarse -> fine, take the first unit with next -1 or distance >= its switch distance (keep wall 320/150/80 m). Matching 0xD238B9DD alone chained 251 of 433 resident prefabs and drew every other prefab's LODs superimposed; by tag: 431/433. Header [7] is NOT the unit count (88 disagree). Units can list a draw twice (identical records) or a PREFIX of another draw (orc tent: 646 of 1,177 tris) - unique_draws drops covered ones.
  • MESH v5 (.wldmsh) = a part's own world-space mesh, the PRFB tables with the vb at 0x2C (header [3] draws, [4] formats, [9] vb bytes, [10] ib bytes); materials index the part's WDSC. Draws wider than 20 km are sky domes / vista cards (night01 504 km, mt_v01 960 km): skipped.
  • TEXTURE ARRAYS carry ~90% of the world's triangles (36 of ~126 materials; terrain shells, cliffs, ruins, orc furnishings). TEXA v1: header + own path + slice source paths, then a DX10 DDS (arraySize = slices, slice-major full mip chains, the tier below the header's; slack 0 on every array read). Six shader trees, one algorithm (pass-0 PS disassembled): w = (MASK + bias)
  • tHeightMap(uv0 * k_fMapTileRate); top two channels -> k_vSliceIndices; t = saturate((w1 - w2) / k_fBlendSmoothness); albedo = lerp((A+B)/2, B, t) [* vertex colour]. MASK = tMaskMap(uv0) on spec_*_tmask, tMaskMap(uv1) on spec2uv_*, the vertex colour on *_vmask (which then does not multiply). Parameters by NAME (cbuffer order differs between trees). Bakes: uv0 masks per MATERIAL over [0,1] (tile rates are integers); uv1 / vertex masks per DRAW on a generated atlas of uv0 islands (<= 512 texels per uv0 unit, power-of-two square sized to the draw). Baking in uv1 itself fails: 15-20% of a building's triangles have zero uv1 area and 42% of texels were claimed twice (atlas: 0.09%). A draw no atlas holds (100 m zipline rope = one uv0 strip) gets its dominant layer, tiling. Normal / spec arrays not baked.
  • Measured capture (Cirith Ungol, radius 150 m): 13 resident parts, 828 placements, 826 instances drawn at their engine LOD = 1.08M triangles from 408K unique (1.62M before the tag / empty-unit / contained-draw fixes); 49 array materials (11 per-material, 37 per-draw atlases, 1 dominant layer); all 173 world primitives / 100 materials textured; 75 MB GLB, ~280 s with warm caches (aire/data/capture/world_cache, tex_cache/arrays). The ground below the walkways is open chasm: the region's floor is a 960 km vista card 324 m down.
  • Not covered: vegetation (.veggrid), decals, water, the lighting layers, destructible / animated prefab .mesh pieces (live objects, still markers), array normal / spec maps.
  • TERRAIN HEIGHTFIELD - CRACKED + MESHED 2026-10-07 (offline; aire/formats/terr.py, aire/capture/terrain.py, call("megaworld_terrain") -> <region>_terrain.glb). Every region's MAIN part ships a TERR v9 (<region>.terrain; layer parts carry empty 12-byte ones; Barad-dur has none). Read exactly as the engine's only reader sub_7AC0F4 does: per terrain u32[2] root grid (4x4 / 8x8), pos f32[3], quat, extent f32[2], height range, f32 f3c (400; desert 500, Black Gate 1000), 4 u32, f32, 4 u32 (NODE COUNT third), u16-length material + global texture (32x32 flag map, one cell per depth-3 node, meaning open), u32, then NODE COUNT x {u32 flags; if !(flags & 0x20): f32 min, f32 max, u32 tile}, then TILE COUNT x {3 u16-length texture paths, u32}. Ends exactly at EOF in every region.
  • Nodes are grid x grid quadtrees in PRE-ORDER: flags bits 0-3 = children present, 0x40 root, 0x20 no data. min/max are NORMALIZED (tile L16 / 65535 equals them, 99.8%+ of tiles).
  • Every ROOT names tile 0 = the region OVERVIEW (heights grid x 64 + 4, maps grid x 128 + 4): a root reads its own block. Deeper nodes: own 68 x 68 L16 tile, two 132 x 132 BGRA maps. Sample grid border 1 (sample i at 1 + i), maps border 2; child bit b -> quadrant (b & 1, b >> 1); parent/child samples agree exactly (97.9% bit-exact, worst 0.17%).
  • World placement, measured by the placements standing on it (128 mappings per region): U = (x - pos.x)/size + 0.5, V = (z - pos.z)/size + 0.5 (pos = CENTRE), y = pos.y + h * range, root r at (r % grid, r // grid), tile column = U, row = V. Share in the best 1 m window: Cirith Ungol 27% @ -1.6 cm, Seregost 37% @ -0.1, Lithlad 30% @ -0.9, Gorgoroth 33%, Nurnen 50%, Minas Ithil 42%, Black Gate 28% (rivals 3-14%).
  • Tile NAMES lie by a folder: TERR asks worlds\retail\volcano\volcano.hm_00_1ter.tex, the entry is ...\volcano\sectionsandlayers\volcano.hm_00_1ter.tex (mtnpass the reverse: a folder DROPPED). mesh_index.loose() rule variant_inserted takes a unique basename whose folders are a superset. Gorgoroth 563/564 and Nurnen 815/846 tiles resolve only so.
  • Material = disp_terrain.fxo, PS + DS disassembled: map 1 = 4 texture-ARRAY SLICE INDICES (BGRA bytes), map 2 = their weights (sum 255). The PS accumulates weight x bilinear factor of the 4 neighbouring texels into a 24-slot per-slice table, keeps the 4 heaviest (renormalised), samples diffuse / normal (X in G, Y in A) / spec / detail-height (G) arrays at world (x, z) / tile (DS o1.xy = world.xz / cb0[30].w), height-blends b = saturate((w(h+0.01) - max(max_j m_j - s, 0)) / s), s = k_fBlendSmoothness, x vertex colour. Index 255 = outside the 24-slot table = no layer: it traces the outside of the play area and interior pockets (fort, caves) - 91% of placements stand on valid cells - so the mesh drops those cells as HOLES. LEADS: tile repeat = f3c; the PS also discards on an unidentified t0; vertex colour white; desert macro tint not applied.
  • Output: one node per root cell, native density (drawn ground is all depth 3 = 0.63 m cells, coarse quadrants are all hole), T-junction edges snapped to the coarser neighbour (85,516 shared vertices, 0.000 cm disagreement), normals from the padded field, per-root albedo bake (2048^2, 14 s/root, cached in aire/data/capture/terrain_cache). Cirith Ungol: 2.35M tris, 85 MB, 199 s; imported into UE level Regions/mtnpass_terrain, mapping 0.005 cm.

Mega-Mordor COMPACT map + playable Talion (BUILT 2026-10-07, headless-verified, NOT yet seen by the user)

User asked for "it all very close, not spread apart, one full single region traversable", a C++ project and Talion with his move set. Unreal project <local path> (UE 5.8, C++ module MegaMordor, built with Build.bat MegaMordorEditor Win64 Development - allowed for THIS project).

  • Compact layout (aire/capture/megaworld_compact.py, build_compact): footprints at 0.18 x the geo layout, slid apart along the axis of least overlap until every pair is 150 m apart (4.75 x 2.3 km, bearings kept, median change 3 deg); each region's ground levelled to 0. Built from the SPREAD GLBs without re-decoding: retarget_glb moves the root node and cuts what lies outside footprint + 55 m or in a neighbour's half (prefab instances by pivot, world meshes and terrain by triangle centroid, 1-2 s per GLB). Backdrops rebuilt, kept only outside the cluster's convex hull + 250 m (Mount Doom's peak, 839 m, survives 1.6 km north). Barad-dur is a STRUCTURE: its placements are the arena on TOP of the tower and the tower body down to -529 m, so its ground = the tower foot (stands ~600 m tall) and the connector land runs on under it.
  • Region edges are not walkable rims (MEASURED on rings outside every footprint): surface heights 10 m out span -196..+294 m around the region's ground; only 24-86% fall in [-40, +80] m. The connector seeds on terrain / world mesh, else the LOWEST surface, clamped to [-40, +80] m - cliffs and chasms stay the regions' own.
  • UE: /Game/MegaMordorCompact/..., map /Game/MegaMordorCompact/Maps/MegaMordorCompact (EditorStartupMap + GameDefaultMap), Scripts/import_compact.sh (terrain levels reuse the spread map's real-time material instances: mode "assign"). The spread map stays as built.
