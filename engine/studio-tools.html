MCP tools + Studio Hub (BUILT 2026-10-20) - use these instead of python -c

.mcp.json registers the native MCP server sowce (aire/mcp, stdlib JSON-RPC over stdio, never imports AIRE). Every tool goes to the SoW:CE Studio Hub (aire/hub; started on demand, one per user, stops after 90 idle min): ONE warm AIRE worker process (crash-isolated; it reloads by itself before the next call when aire/ or tools/ .py files changed), background jobs, a result store, the Blender peer, and the link server it starts / stops. Full reference: aire/documents/STUDIO_HUB.md.

  • mcp__sowce__aire(action, args) replaces python -c "from aire.headless import call...": no shell quoting, warm caches (MEASURED: concept explain 13.4 s cold vs 2.0 s warm; RVA explain 3.0 s vs 0.04 s), every result stored as r<N> and paged with aire_result (path / grep / save_to) instead of cut at 30 KB. aire_help(query | action) = the searchable catalog with file:line. A call past timeout_s becomes a ticket (never killed); background=true = its own job; aire_job follows both.
  • World: world_link starts the link server (THE main-thread bridge owner); world_objects, world_move (sow | blender space, delta / yaw, dry_run; keep flags = untouched components keep the game's bytes), world_clone, world_revert share the link's journal with Blender.
  • Blender: blender_status / scene / python / op drive the SoW Live add-on 1.4.0 (installed as a Blender 5.2 extension; sidebar N > SoW Live > AI Hub > Connect). Each AI Python run = one undo step.
  • Mods: mods op=list|validate|probe|apply|keep|stop|revert|from_link (World Studio). Studio writes are refused while that mod's keeper runs (one journal writer per mod).
  • The main-thread bridge is locked across processes: exec_main / cancel_main hold the named mutex Local\SoWCE.MainThreadBridge for the whole round trip (MEASURED with a fake poller: without it, a second command REPLACED the first, which reported "queued" and never ran). A caller that cannot get it within timeout gets busy and nothing is sent.
  • New World Studio kinds (open world, any region; aire/studio/kinds_world.py): object_xform (a named object at a world transform; link Bridge route with the mod's own objects_journal.json), object_clone (world-anchored live_clone), gadb_field (any named record's field; RecordLinks checked against the declared target). New actions: studio_mods, studio_save_edits(mod, items), studio_from_link(mod), blender_link_install.
  • Hub state: %LOCALAPPDATA%\SoWCE\hub\ (hub.json = port 47910 + token; hub / worker / link / mcp logs; jobs/; results/). Hub code changes need hub op=restart (keeps link, jobs, Blender); MCP adapter changes need /mcp.
  • LIVE DEMO 2026-10-20 (MEASURED by read-back; IN-GAME CONFIRMED by the user: "Yes that worked nice"): hub world_move + world_clone; a 9-crate ring laid out by blender_python on the captured ground and pushed by the add-on (9/9, read-back 0.000 cm); mods from_link -> probe OK -> world_revert -> probe FAIL -> mods apply (9 byte-exact) -> probe OK; the keeper put back a crate lifted 3 m. NOT RUN: a keeper re-apply after a real re-stream (fast travel / cell reload). Demo drivers saved: scripts/studio/hub_demo.py / hub_demo_ring.py, scripts/blender/live_demo_start.py (all of today's tools: scripts/studio/README.md).
  • End of a session - turning every live mod off: aire/documents/STUDIO_HUB.md "Turning everything off" (keepers, watchers AND any supervisor loop around a watcher - another session's while true; do python <watcher>; sleep 10; done restarted the dismember / Shrine watcher within seconds until the loop's own shell was stopped; then disarm, live_bundle_unload(path=...), live_vfs_unmount, anim_live_revert).
